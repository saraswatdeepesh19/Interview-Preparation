# MongoDB indexes and aggregation pipeline

---

## 🟢 Junior Level

### 1. What is an index?

An **index** is an extra sorted data structure (a B-tree in MongoDB) that lets the database find documents without scanning the whole collection. Like the index at the back of a book: you look up "Cassandra" and jump to page 214.

Without an index, a query does a **COLLSCAN** (reads every document). With one it does an **IXSCAN**. Every collection has a unique index on `_id` automatically.

```java
MongoCollection<Document> users = db.getCollection("users");

users.createIndex(Indexes.ascending("email"), new IndexOptions().unique(true));
users.createIndex(Indexes.compoundIndex(Indexes.ascending("status"), Indexes.descending("createdAt")));
```

### 2. What is the aggregation pipeline?

A pipeline passes documents through **stages**; each stage transforms them (filter, group, sort, reshape). It is MongoDB's equivalent of `WHERE` + `GROUP BY` + `JOIN` + `ORDER BY`.

```java
// Total order amount per customer for COMPLETED orders, top 5
List<Document> result = orders.aggregate(List.of(
    Aggregates.match(Filters.eq("status", "COMPLETED")),
    Aggregates.group("$customerId", Accumulators.sum("total", "$amount")),
    Aggregates.sort(Sorts.descending("total")),
    Aggregates.limit(5)
)).into(new ArrayList<>());
```

## 🟡 Middle Level

### 1. Index types

| Type | Use |
| :--- | :--- |
| Single field | Equality / range on one field |
| **Compound** | Multi-field queries and sorts; order matters |
| Multikey | Auto-created on array fields (one entry per element) |
| Text | Basic full-text search (one per collection) |
| Geospatial (`2dsphere`) | `$near`, `$geoWithin` |
| Hashed | Hash-sharding, equality only |
| **TTL** | Auto-delete documents after N seconds (on a date field) |
| **Partial** | Index only documents matching a filter (smaller) |
| **Sparse / Unique** | Skip missing fields / enforce uniqueness |
| Wildcard | Index unknown/dynamic field names |

### 2. Compound index: the ESR rule

Order fields as **E**quality, **S**ort, **R**ange. For a query `status = ? AND createdAt > ? ORDER BY score DESC` the index should be `{status: 1, score: -1, createdAt: 1}`.

**Prefix rule:** index `{a, b, c}` supports queries on `a`, `a+b`, `a+b+c`, but not `b` alone.

```java
// Partial + TTL examples
orders.createIndex(Indexes.ascending("customerId", "createdAt"),
    new IndexOptions().partialFilterExpression(Filters.eq("status", "OPEN")));

sessions.createIndex(Indexes.ascending("lastSeen"),
    new IndexOptions().expireAfter(30L, TimeUnit.MINUTES));
```

### 3. Covered queries

If all fields in the filter and projection are in the index (and `_id` is excluded from projection) MongoDB answers from the index only (`PROJECTION_COVERED`), never touching documents.

### 4. Common pipeline stages

| Stage | Purpose |
| :--- | :--- |
| `$match` | Filter (put as early as possible; can use indexes) |
| `$project` / `$addFields` / `$set` | Reshape fields |
| `$group` | Aggregate with accumulators (`$sum $avg $min $max $push $addToSet`) |
| `$sort`, `$limit`, `$skip` | Order and paginate |
| `$unwind` | Flatten arrays |
| `$lookup` | Left outer join to another collection |
| `$facet` | Multiple sub-pipelines in parallel (faceted search) |
| `$bucket` | Histogram groups |
| `$merge` / `$out` | Write results to a collection (materialised views) |

### 5. Spring Data MongoDB typed aggregation

```java
import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

public List<CustomerTotal> topCustomers() {
    Aggregation agg = newAggregation(
        match(Criteria.where("status").is("COMPLETED")),
        group("customerId").sum("amount").as("total").count().as("orders"),
        sort(Sort.Direction.DESC, "total"),
        limit(5),
        project("total", "orders").and("_id").as("customerId").andExclude("_id"));
    return mongoTemplate.aggregate(agg, "orders", CustomerTotal.class).getMappedResults();
}

public record CustomerTotal(String customerId, double total, int orders) {}
```

Declaring indexes on entities:

```java
@Document("orders")
@CompoundIndex(name = "status_created", def = "{'status': 1, 'createdAt': -1}")
public class OrderDoc {
    @Id String id;
    @Indexed String customerId;
    String status;
    Instant createdAt;
}
```

(Spring Boot 3.x/Spring Data MongoDB 4.x: automatic index creation is **disabled by default**; set `spring.data.mongodb.auto-index-creation=true` or manage indexes via migrations.)

### 6. Common mistakes

- Too many indexes: each index slows writes and consumes RAM.
- Wrong order in compound indexes, so sort cannot use the index.
- `$match` after `$group` instead of before.
- Using `skip(n)` for deep pagination: O(n). Use **range pagination** (`createdAt < lastSeen`).
- `$lookup` on unindexed foreign field (full scan per input doc).
- Regex with leading wildcard (`/.*abc/`) cannot use an index efficiently.

## 🔴 Senior Level

### 1. Reading plans and avoiding pitfalls

```javascript
db.orders.find({ status: "OPEN", customerId: "c1" }).sort({ createdAt: -1 })
         .explain("executionStats")
```

Look for `IXSCAN` -> `FETCH` -> (no `SORT`). A `SORT` stage means the index doesn't provide order. `keysExamined >> nReturned` suggests a low-selectivity prefix or wrong ordering. Use `hint()` only to diagnose, never leave in code permanently.

### 2. Aggregation internals and limits

- Each stage's output is streamed in batches; blocking stages (`$sort` without index, `$group`) hold memory: **100 MB per stage** unless `allowDiskUse: true` (default true from 6.0 via `allowDiskUseByDefault`).
- Documents between stages are limited to 16 MB.
- The optimizer reorders: `$match` + `$sort` pushdown, `$sort` + `$limit` coalescing (top-k sort uses bounded memory), `$project` pushdown to cover queries.
- On sharded clusters `$group` splits into per-shard partial groups plus a merge on one shard (or mongos); `$lookup` and `$out` constrain execution to a "merger shard".

```java
Document explain = orders.aggregate(pipeline).explain(ExplainVerbosity.EXECUTION_STATS);
```

### 3. Index build and maintenance in production

- Since 4.4, index builds hold locks only at start/end ("hybrid" builds) but still use I/O and may lag secondaries; build off-peak.
- Check index usage with `$indexStats`; drop unused indexes after observation for a full business cycle. Use `hideIndex()` (4.4+) to test removal safely.
- Index size must fit in RAM along with the hot working set; check `db.collection.totalIndexSize()`.
- TTL monitor runs every 60 s; deletions are not instantaneous and generate oplog traffic.

### 4. Performance example: pagination

```java
// Keyset (seek) pagination - constant time at any depth
public List<OrderDoc> page(String customerId, Instant before, int size) {
    Query q = new Query(Criteria.where("customerId").is(customerId)
            .and("createdAt").lt(before))
        .with(Sort.by(Sort.Direction.DESC, "createdAt"))
        .limit(size);
    return mongoTemplate.find(q, OrderDoc.class);   // uses {customerId:1, createdAt:-1}
}
```

### 5. Alternatives to heavy aggregation

For analytics on large data, avoid running multi-minute pipelines on the primary: use **analytics nodes** (secondary tagged), **materialised views via `$merge`**, change-stream-driven incremental aggregates, or export to a warehouse (ClickHouse, BigQuery). Atlas Search/Elasticsearch handle faceting better than `$facet` on big data.

### 6. Edge cases

- Collation: queries and indexes must use the same collation (case-insensitive indexes).
- Unique index with `null`/missing values: only one document may omit the field unless the index is partial/sparse.
- Index on low-cardinality fields (boolean) is rarely helpful alone.

## 🎯 Interview Cheat Sheet

### 30-second pitch
"Indexes are B-trees that turn collection scans into index scans; compound indexes follow equality-sort-range and the prefix rule. The aggregation pipeline is a staged data-processing framework: match early, group, sort, lookup. I verify everything with explain and limit indexes to what queries really need."

### Must-know bullets
- ESR rule and prefix rule for compound indexes.
- Covered queries avoid fetching documents.
- TTL, partial, unique, text, 2dsphere indexes exist.
- Put `$match` and `$limit` early; `$sort` needs an index to avoid memory limits.
- Keyset pagination beats `skip`.
- Spring Data auto-index creation is off by default in newer Boot.

### Common follow-ups
- How would you index a query with equality, sort and range?
- What does explain's COLLSCAN mean?
- How does `$lookup` perform at scale?
- How do you add an index to a huge production collection safely?

### 🚩 Red flags
- Indexing every field "just in case".
- `skip(100000)` pagination.
- No explain-based verification.
