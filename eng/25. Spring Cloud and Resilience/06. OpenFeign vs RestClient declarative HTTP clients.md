# OpenFeign vs RestClient declarative HTTP clients

---

## 🟢 Junior Level

### What is a declarative HTTP client?

Instead of writing URL strings, headers, and JSON parsing by hand for every remote call, you **declare an interface** describing the remote API, and the framework generates the implementation. Spring offers two main styles:

- **OpenFeign** (`spring-cloud-starter-openfeign`) — annotation-driven client using `@FeignClient`.
- **HTTP Interface** (Spring Framework 6+) — `@HttpExchange` interfaces backed by `RestClient` (blocking) or `WebClient` (reactive).

### Analogy

Ordering from a menu instead of dictating a recipe to the chef. You name the dish (method), the kitchen (framework) handles the details.

### OpenFeign example

```java
@EnableFeignClients
@SpringBootApplication
public class OrderApplication { /* main */ }

@FeignClient(name = "inventory-service")
public interface InventoryClient {

    @GetMapping("/items/{sku}")
    ItemDto getItem(@PathVariable("sku") String sku);

    @PostMapping("/items/{sku}/reserve")
    void reserve(@PathVariable("sku") String sku, @RequestBody ReserveRequest request);
}

public record ItemDto(String sku, int available) {}
public record ReserveRequest(int quantity) {}
```

Inject `InventoryClient` like any bean. `name` is resolved by service discovery and load-balanced.

### HTTP interface with RestClient (Spring Boot 3.2+)

```java
public interface InventoryApi {

    @GetExchange("/items/{sku}")
    ItemDto getItem(@PathVariable String sku);

    @PostExchange("/items/{sku}/reserve")
    void reserve(@PathVariable String sku, @RequestBody ReserveRequest request);
}

@Configuration
class ClientConfig {
    @Bean
    InventoryApi inventoryApi(RestClient.Builder builder) {
        RestClient client = builder.baseUrl("http://inventory-service").build();
        return HttpServiceProxyFactory
                .builderFor(RestClientAdapter.create(client))
                .build()
                .createClient(InventoryApi.class);
    }
}
```

Make the injected `RestClient.Builder` a `@LoadBalanced` one if using logical names.

## 🟡 Middle Level

### Comparison

| Aspect | OpenFeign | HTTP Interface + RestClient |
| :--- | :--- | :--- |
| Owner | Spring Cloud (Feign from OpenFeign org) | Spring Framework core |
| Annotations | `@FeignClient`, Spring MVC annotations | `@HttpExchange` family |
| Blocking/reactive | Blocking only | Blocking (`RestClient`) or reactive (`WebClient`) |
| Discovery/LB | Built in by name | Via `@LoadBalanced` builder |
| Circuit breaker | `spring.cloud.openfeign.circuitbreaker.enabled=true` | Wrap with Resilience4j annotations/decorators |
| Interceptors | `RequestInterceptor` | `ClientHttpRequestInterceptor` |
| Error decoding | `ErrorDecoder` | `defaultStatusHandler` |
| Virtual threads | Works | Works |
| Native image | Hints needed | First-class |

Guidance in 2024+: for new code prefer HTTP interfaces on `RestClient`; keep Feign where existing infrastructure (fallbacks, contract tests, shared client JARs) is deeply invested. `RestTemplate` is in maintenance mode.

### Feign configuration

```yaml
spring:
  cloud:
    openfeign:
      circuitbreaker:
        enabled: true
      client:
        config:
          default:
            connect-timeout: 1000
            read-timeout: 3000
            logger-level: basic
          inventory-service:
            read-timeout: 1500
```

Feign fallbacks:

```java
@FeignClient(name = "inventory-service", fallbackFactory = InventoryFallbackFactory.class)
public interface ResilientInventoryClient {
    @GetMapping("/items/{sku}")
    ItemDto getItem(@PathVariable("sku") String sku);
}

@Component
class InventoryFallbackFactory implements FallbackFactory<ResilientInventoryClient> {
    @Override
    public ResilientInventoryClient create(Throwable cause) {
        return sku -> new ItemDto(sku, 0); // degraded: assume none available
    }
}
```

`fallbackFactory` gives access to the cause, unlike plain `fallback`.

### Error handling with RestClient

```java
RestClient client = builder.baseUrl("http://inventory-service")
    .defaultStatusHandler(HttpStatusCode::is5xxServerError, (req, res) -> {
        throw new RemoteServiceException("inventory 5xx: " + res.getStatusCode());
    })
    .defaultStatusHandler(status -> status.value() == 404, (req, res) -> {
        throw new ItemNotFoundException();
    })
    .build();

class RemoteServiceException extends RuntimeException {
    RemoteServiceException(String m) { super(m); }
}
class ItemNotFoundException extends RuntimeException {}
```

### Common mistakes

- Relying on Feign **default timeouts** (connect 10 s / read 60 s without Spring Cloud defaults override) → thread exhaustion.
- Feign's own `Retryer` is `NEVER_RETRY` under Spring Cloud by default; teams then add retries at three layers (Feign, LoadBalancer, Resilience4j) → multiplicative retries. Choose one layer.
- Sharing a `@FeignClient` interface carrying server-side `@RestController` annotations in an API jar: tight coupling and breaking releases.
- Forgetting `@PathVariable("name")` explicit names in Feign when compiled without `-parameters`.
- Catching `FeignException` and swallowing the status code.

## 🔴 Senior Level

### Under the hood

**Feign:** `@EnableFeignClients` registers `FeignClientFactoryBean`s; each creates a JDK dynamic proxy. `SpringMvcContract` translates Spring MVC annotations to Feign metadata. Per-client child ApplicationContext (like LoadBalancer) holds `Encoder/Decoder/Client/Retryer`. The HTTP engine is pluggable: default `HttpURLConnection` (no pooling!), so add `feign-hc5` (Apache HttpClient 5) or `feign-okhttp` and enable it:

```yaml
spring:
  cloud:
    openfeign:
      httpclient:
        hc5:
          enabled: true
        max-connections: 200
        max-connections-per-route: 50
        connection-timeout: 1000
```

**HTTP interface:** `HttpServiceProxyFactory` creates a JDK proxy dispatching each method to `HttpExchangeAdapter`, with argument resolvers for `@RequestBody`, `@RequestParam`, `@RequestHeader`, `@PathVariable`. The underlying `RestClient` request factory should be configured with pooling (`JdkClientHttpRequestFactory`, or Apache `HttpComponentsClientHttpRequestFactory`) and timeouts:

```java
HttpComponentsClientHttpRequestFactory factory = new HttpComponentsClientHttpRequestFactory(
    HttpClients.custom()
        .setConnectionManager(PoolingHttpClientConnectionManagerBuilder.create()
            .setMaxConnTotal(200).setMaxConnPerRoute(50).build())
        .build());
factory.setConnectTimeout(Duration.ofSeconds(1));
factory.setConnectionRequestTimeout(Duration.ofMillis(500)); // pool lease timeout
```

(Per-request read timeout is set via `RequestConfig` on the client in HttpClient 5; with Boot 3.4+ use `ClientHttpRequestFactorySettings`/`ClientHttpRequestFactoryBuilder`.)

### Observability

Boot auto-configures `RestClient.Builder` and `WebClient.Builder` with Micrometer observation, so trace headers and `http.client.requests` metrics appear if you build clients **from the injected builder**. For Feign, add `feign-micrometer`/Spring Cloud OpenFeign observation (`spring.cloud.openfeign.micrometer.enabled`). A client built with `RestClient.create()` bypasses this, so propagation silently breaks — a classic tracing gap.

### Blocking and virtual threads

Both client styles block the calling thread. With platform threads, 200 Tomcat threads × slow downstream = saturation. With virtual threads (`spring.threads.virtual.enabled=true`) blocking is cheap, but **pool limits still bound concurrency**; without bulkheads the downstream can be overwhelmed because there's no natural thread cap anymore. Add `Bulkhead`/semaphore limits.

### Testing

Contract-test with WireMock or Spring Cloud Contract; for `RestClient` use `MockRestServiceServer.bindTo(builder)`:

```java
RestClient.Builder builder = RestClient.builder();
MockRestServiceServer server = MockRestServiceServer.bindTo(builder).build();
server.expect(requestTo("/items/A1"))
      .andRespond(withSuccess("{\"sku\":\"A1\",\"available\":5}", MediaType.APPLICATION_JSON));
```

### Edge cases

- Feign decoding of `Optional`/`ResponseEntity<Void>` and 404 semantics (`dismiss404`).
- Large file upload/download: stream instead of buffering to `byte[]`.
- Header propagation (auth token) across threads: use interceptors reading from `SecurityContext` or the observation context, not `RequestContextHolder` on async threads.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Both generate client implementations from interfaces. OpenFeign is the Spring Cloud veteran with built-in discovery, fallbacks, and config per client; HTTP interfaces on `RestClient` are the Spring Framework-native successor with less magic and good native-image support. Both need explicit timeouts, pooling, and a single retry layer.

**Must-know bullets**
- Feign default engine has no pooling; swap to hc5/OkHttp.
- Set connect/read timeouts per client.
- `FallbackFactory` exposes the cause.
- Build clients from the injected builder to keep tracing/metrics.
- Avoid retry duplication across Feign, LB, and Resilience4j.

**Follow-up questions**
- Why is `RestTemplate` discouraged now?
- How do you propagate the bearer token via Feign?
- What happens with virtual threads and unbounded concurrency?

**Red flags**
- Default timeouts in production.
- Sharing controller-annotated interfaces across teams.
- Swallowing `FeignException` status codes.
