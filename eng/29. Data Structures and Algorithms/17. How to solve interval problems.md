# How to solve interval problems

---

## 🟢 Junior Level

Interval problems deal with ranges `[start, end]` — meetings, bookings, time windows, IP ranges. Almost all of them start with the same move: **sort by start** (sometimes by end), then sweep from left to right.

### Two intervals overlap when

```java
boolean overlaps(int[] a, int[] b) {
    return a[0] < b[1] && b[0] < a[1];      // half-open [start, end): touching endpoints don't overlap
}
```

For closed intervals `[start, end]` use `<=`. Clarify which one the problem uses — "meeting 9–10 and 10–11" usually don't conflict.

### Merge overlapping intervals

```java
int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
    List<int[]> merged = new ArrayList<>();
    for (int[] cur : intervals) {
        if (merged.isEmpty() || merged.get(merged.size() - 1)[1] < cur[0]) {
            merged.add(cur.clone());                               // no overlap: start a new block
        } else {
            int[] last = merged.get(merged.size() - 1);
            last[1] = Math.max(last[1], cur[1]);                   // overlap: extend
        }
    }
    return merged.toArray(new int[0][]);
}
// [[1,3],[2,6],[8,10],[15,18]] -> [[1,6],[8,10],[15,18]]
```

O(n log n) for sorting, O(n) for the sweep.

## 🟡 Middle Level

### Insert an interval into a sorted, non-overlapping list

```java
int[][] insert(int[][] intervals, int[] add) {
    List<int[]> out = new ArrayList<>();
    int i = 0, n = intervals.length;
    while (i < n && intervals[i][1] < add[0]) out.add(intervals[i++]);          // entirely before
    int s = add[0], e = add[1];
    while (i < n && intervals[i][0] <= e) {                                     // overlapping: absorb
        s = Math.min(s, intervals[i][0]);
        e = Math.max(e, intervals[i][1]);
        i++;
    }
    out.add(new int[]{s, e});
    while (i < n) out.add(intervals[i++]);                                      // entirely after
    return out.toArray(new int[0][]);
}
```

### Minimum meeting rooms (max overlap)

```java
// Min-heap of end times of ongoing meetings
int minMeetingRooms(int[][] meetings) {
    Arrays.sort(meetings, Comparator.comparingInt(m -> m[0]));
    PriorityQueue<Integer> ends = new PriorityQueue<>();
    for (int[] m : meetings) {
        if (!ends.isEmpty() && ends.peek() <= m[0]) ends.poll();   // a room freed up
        ends.offer(m[1]);
    }
    return ends.size();
}

// Equivalent sweep line: +1 at each start, -1 at each end
int minRoomsSweep(int[][] meetings) {
    int n = meetings.length;
    int[] starts = new int[n], ends = new int[n];
    for (int i = 0; i < n; i++) { starts[i] = meetings[i][0]; ends[i] = meetings[i][1]; }
    Arrays.sort(starts); Arrays.sort(ends);
    int rooms = 0, max = 0, j = 0;
    for (int i = 0; i < n; i++) {
        while (j < n && ends[j] <= starts[i]) { j++; rooms--; }
        rooms++;
        max = Math.max(max, rooms);
    }
    return max;
}
```

### Non-overlapping intervals (greedy by end)
To remove the fewest intervals so the rest don't overlap, **sort by end** and keep each interval that starts after the last kept one ends — the classic activity-selection greedy.

```java
int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[1]));
    int kept = 0, lastEnd = Integer.MIN_VALUE;
    for (int[] iv : intervals) {
        if (iv[0] >= lastEnd) { kept++; lastEnd = iv[1]; }
    }
    return intervals.length - kept;
}
```

## 🔴 Senior Level

### Patterns at a glance

| Question | Sort by | Technique |
| --- | --- | --- |
| Merge overlaps | start | Sweep, extend end |
| Max simultaneous (rooms, concurrent sessions) | start | Min-heap of ends, or sweep line with events |
| Keep max non-overlapping / remove min | end | Greedy |
| Intersection of two sorted interval lists | (already sorted) | Two pointers, advance the one ending first |
| Point in which interval? | start | Binary search (`TreeMap.floorEntry`) |
| Many overlap queries on dynamic data | — | Interval tree / segment tree |

```java
// Lookup which range contains a value (e.g. IP range -> country, price tier)
TreeMap<Long, Range> byStart = new TreeMap<>();
Range find(long x) {
    Map.Entry<Long, Range> e = byStart.floorEntry(x);
    return (e != null && x < e.getValue().end()) ? e.getValue() : null;
}
```

### Sweep line with event ordering
When building events `(time, +1 / -1)`, define the order for equal times explicitly: for half-open intervals process **ends before starts** at the same time (a meeting ending at 10 frees the room for one starting at 10). Getting this tie-break wrong is the most common bug.

### Backend applications
* **Booking systems** — preventing double booking in the database with a PostgreSQL exclusion constraint on `tstzrange` (no application-level race conditions):

```sql
create extension if not exists btree_gist;
create table room_bookings (
  room_id bigint not null,
  during  tstzrange not null,
  exclude using gist (room_id with =, during with &&)     -- no overlapping ranges per room
);
```

* **Rate limiting windows, SLA calculations, on-call schedules, maintenance windows** — merging and intersecting time ranges, with careful time zones and DST (store UTC instants; convert at the edges).
* **Calendar free/busy** — merge busy intervals of all participants, then find gaps.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Interval problems usually start by sorting — by start for merging and overlap counting, by end for greedy selection. Merging is a single sweep extending the last end; meeting rooms is a min-heap of end times or a sweep line with +1/−1 events; removing the fewest overlaps is the activity-selection greedy. I clarify open vs closed endpoints and tie-breaking, and in databases I'd prevent double bookings with a range exclusion constraint.

**Must know:**
* Overlap test and half-open vs closed endpoints.
* Merge, insert, meeting rooms, non-overlapping intervals, intersections.
* Sweep line with correct tie-break order.
* `TreeMap.floorEntry` for point-in-range lookups.
* PostgreSQL `tstzrange` + `EXCLUDE USING gist`.

**Common follow-ups:**
* Merge intervals arriving as a stream?
* Find free slots common to several calendars.
* How would you prevent double booking under concurrency?

**Red flags:** O(n²) pairwise comparisons; forgetting to sort; ignoring endpoint semantics.
