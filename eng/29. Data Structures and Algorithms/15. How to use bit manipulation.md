# How to use bit manipulation

---

## 🟢 Junior Level

Computers store integers as binary. **Bit manipulation** works directly on those bits with operators:

| Operator | Meaning | Example (`a = 0b1100`, `b = 0b1010`) |
| --- | --- | --- |
| `&` | AND | `a & b = 0b1000` |
| `\|` | OR | `a \| b = 0b1110` |
| `^` | XOR (1 if bits differ) | `a ^ b = 0b0110` |
| `~` | NOT (flip all bits) | `~0 = -1` |
| `<<` | Shift left (×2 per position) | `1 << 3 = 8` |
| `>>` | Arithmetic shift right (keeps sign) | `-8 >> 1 = -4` |
| `>>>` | Logical shift right (fills with 0) | `-8 >>> 28 = 15` |

### Everyday tricks

```java
boolean isOdd(int x)          { return (x & 1) == 1; }      // careful: -3 & 1 == 1, works for negatives
boolean isPowerOfTwo(int x)   { return x > 0 && (x & (x - 1)) == 0; }
int     setBit(int x, int i)  { return x | (1 << i); }
int     clearBit(int x, int i){ return x & ~(1 << i); }
boolean hasBit(int x, int i)  { return (x & (1 << i)) != 0; }
int     toggleBit(int x, int i){ return x ^ (1 << i); }
int     lowestSetBit(int x)   { return x & -x; }             // 0b10100 -> 0b00100
```

Java's two's-complement integers: `int` is 32 bits, `long` 64 bits; `-x == ~x + 1`.

## 🟡 Middle Level

### XOR properties and the "single number" family
`x ^ x = 0`, `x ^ 0 = x`, XOR is commutative and associative. So XOR-ing all elements cancels pairs:

```java
// Every number appears twice except one
int singleNumber(int[] nums) {
    int r = 0;
    for (int x : nums) r ^= x;
    return r;
}

// Missing number in 0..n
int missingNumber(int[] nums) {
    int r = nums.length;
    for (int i = 0; i < nums.length; i++) r ^= i ^ nums[i];
    return r;
}
```

### Counting bits

```java
int popCount(int x) { return Integer.bitCount(x); }          // intrinsic POPCNT instruction on modern CPUs

// Brian Kernighan: each iteration clears the lowest set bit
int popCountManual(int x) {
    int c = 0;
    while (x != 0) { x &= x - 1; c++; }
    return c;
}

// dp: bits(i) = bits(i >> 1) + (i & 1)
int[] countBits(int n) {
    int[] r = new int[n + 1];
    for (int i = 1; i <= n; i++) r[i] = r[i >> 1] + (i & 1);
    return r;
}
```

Useful JDK helpers: `Integer.bitCount`, `Integer.highestOneBit`, `Integer.numberOfTrailingZeros`, `Integer.numberOfLeadingZeros`, `Integer.reverse`, `Integer.rotateLeft`, `Long` equivalents.

### Subsets with bitmasks

```java
List<List<Integer>> subsets(int[] nums) {
    int n = nums.length;
    List<List<Integer>> all = new ArrayList<>(1 << n);
    for (int mask = 0; mask < (1 << n); mask++) {
        List<Integer> s = new ArrayList<>();
        for (int i = 0; i < n; i++) if ((mask & (1 << i)) != 0) s.add(nums[i]);
        all.add(s);
    }
    return all;
}
```

## 🔴 Senior Level

### Bit manipulation in real Java systems
* **`HashMap` index**: capacity is a power of two, so `index = (n - 1) & hash` replaces a slow modulo; `hash ^ (hash >>> 16)` spreads high bits into low bits.
* **`ConcurrentHashMap`, `ThreadPoolExecutor`**: `ctl` packs run state (3 bits) and worker count (29 bits) into one `AtomicInteger` for atomic updates.
* **`EnumSet`** (`RegularEnumSet`) stores up to 64 enum constants in one `long` — set operations are single instructions.
* **`BitSet`** — compact boolean arrays (1 bit per flag): feature flags, Bloom filters, sieve of Eratosthenes, roaring-bitmap-style indexes.
* **Permissions/flags** in protocols and file formats (Unix mode bits, TCP flags).

```java
enum Permission { READ, WRITE, DELETE, SHARE }
EnumSet<Permission> granted = EnumSet.of(Permission.READ, Permission.SHARE);   // one long internally
boolean canWrite = granted.contains(Permission.WRITE);
```

### Pitfalls in Java
* **Shift distance is masked**: `1 << 32 == 1` for `int` (distance taken mod 32); use `1L << 32` for longs.
* **Sign extension**: `(byte) 0xF0 >> 4` is `-1` because the byte is promoted to a negative `int`; use `(b & 0xFF) >>> 4`.
* `>>` vs `>>>`: average of two ints without overflow is `(a + b) >>> 1` for non-negative values (used in `Arrays.binarySearch`), or `a + ((b - a) >> 1)`.
* Operator precedence: `x & 1 == 0` parses as `x & (1 == 0)` — a compile error in Java (int & boolean); always parenthesize.

### Advanced techniques
* **Gray code**: `i ^ (i >> 1)`.
* **Bitmask DP**: traveling salesman `dp[mask][i]` with n ≤ ~20.
* **Iterate over subsets of a mask**: `for (int s = mask; s > 0; s = (s - 1) & mask)`.
* **Single number II** (every element three times except one): count bits modulo 3, or the `ones/twos` state machine.
* **Bloom filters**: k hash functions setting bits in a `BitSet`; tests membership with no false negatives and tunable false-positive rate — used in Cassandra SSTables, RocksDB, and caches to avoid disk lookups.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Bit manipulation uses AND, OR, XOR, NOT and shifts on two's-complement integers. Key tricks: `x & (x - 1)` clears the lowest set bit (power-of-two checks, popcount), `x & -x` isolates it, XOR cancels pairs (single number, missing number), and masks enumerate subsets. In Java I know the shift masking, sign-extension and `>>>` pitfalls, and where the JDK uses bits — `HashMap` indexing, `EnumSet`, `BitSet`, packed atomic state.

**Must know:**
* `& | ^ ~ << >> >>>` semantics; two's complement.
* Set/clear/toggle/test bit; power of two check.
* XOR tricks; `Integer.bitCount`.
* Bitmask subset enumeration.
* `1 << 32` pitfall; byte sign extension.

**Common follow-ups:**
* How does `HashMap` compute bucket indexes?
* Count bits for all numbers 0..n in O(n).
* Find the two numbers that appear once when all others appear twice.

**Red flags:** `x % 2 == 1` for odd checks on negatives (it's -1); missing parentheses with `&`.
