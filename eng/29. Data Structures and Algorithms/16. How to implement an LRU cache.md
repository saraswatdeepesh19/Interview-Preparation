# How to implement an LRU cache

---

## 🟢 Junior Level

An **LRU (Least Recently Used) cache** has a fixed capacity; when it's full and a new key arrives, it evicts the key that was **used least recently**. Both `get` and `put` should run in **O(1)**.

The classic design combines two structures:
* a **hash map** from key → node, for O(1) lookup,
* a **doubly linked list** ordered by recency, for O(1) move-to-front and remove-from-tail.

### The quick Java answer: `LinkedHashMap`

```java
public class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LruCache(int capacity) {
        super(16, 0.75f, true);              // accessOrder = true: get() moves entries to the end
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;            // evict least recently accessed after insertion
    }
}
```

Mention it first in an interview — then implement it from scratch if asked.

## 🟡 Middle Level

### From scratch: HashMap + doubly linked list

```java
public class LruCache<K, V> {
    private final class Node {
        K key; V value; Node prev, next;
        Node(K k, V v) { key = k; value = v; }
    }

    private final int capacity;
    private final Map<K, Node> index = new HashMap<>();
    private final Node head = new Node(null, null);   // sentinel: most recent side
    private final Node tail = new Node(null, null);   // sentinel: least recent side

    public LruCache(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity must be > 0");
        this.capacity = capacity;
        head.next = tail;
        tail.prev = head;
    }

    public V get(K key) {
        Node n = index.get(key);
        if (n == null) return null;
        moveToFront(n);
        return n.value;
    }

    public void put(K key, V value) {
        Node n = index.get(key);
        if (n != null) {                     // update existing
            n.value = value;
            moveToFront(n);
            return;
        }
        if (index.size() == capacity) {      // evict LRU
            Node lru = tail.prev;
            unlink(lru);
            index.remove(lru.key);
        }
        Node fresh = new Node(key, value);
        index.put(key, fresh);
        addFirst(fresh);
    }

    private void moveToFront(Node n) { unlink(n); addFirst(n); }

    private void addFirst(Node n) {
        n.prev = head;
        n.next = head.next;
        head.next.prev = n;
        head.next = n;
    }

    private void unlink(Node n) {
        n.prev.next = n.next;
        n.next.prev = n.prev;
    }
}
```

Sentinel nodes remove all `null` checks for empty/edge cases. Each node stores its key so eviction can remove it from the map.

### Testing the edge cases
* Capacity 1; `put` existing key updates value **and** recency; `get` of missing key; eviction order after mixed gets/puts.

## 🔴 Senior Level

### Thread safety
The structure above isn't thread-safe — every `get` mutates the list. Options:
* `Collections.synchronizedMap(new LruCache<>(...))` or a single `ReentrantLock` — simple, but all operations serialize (fine for low contention).
* **Striping** (split into N independent LRU segments by key hash) — approximates global LRU with less contention.
* In production, use **Caffeine**: concurrent, near-optimal hit rates with **W-TinyLFU** (an admission filter based on frequency sketches plus a windowed LRU), amortized O(1), with read/write buffers that record accesses without locking the main structure.

```java
Cache<String, Product> cache = Caffeine.newBuilder()
        .maximumSize(10_000)
        .expireAfterWrite(Duration.ofMinutes(10))
        .recordStats()
        .build();
```

### LRU limitations
* **Scan pollution** — a one-time scan of many keys (a batch job, a crawler) evicts the genuinely hot working set. LFU-ish policies (TinyLFU), **LRU-K**, **2Q**, **ARC**, or segmented LRU (probation + protected segments) resist this.
* **Strict LRU bookkeeping** on every read is costly under concurrency; real systems approximate. Redis uses *approximated LRU*: sample `maxmemory-samples` keys (default 5) and evict the oldest among them; Redis also offers LFU with logarithmic counters and decay. Linux page cache uses a two-list (active/inactive) approximation.

### Variants interviewers ask for
* **LFU cache in O(1)**: map key → node, map frequency → doubly linked list of nodes, track `minFreq`; on access move node to `freq+1` list.
* **TTL + LRU**: store expiry per entry; lazily check on `get`, plus periodic cleanup or a priority queue of expiries.
* **Size-weighted eviction**: evict by total bytes, not entry count (`Caffeine.maximumWeight` with a `Weigher`).

## 🎯 Interview Cheat Sheet

**30-second pitch:** An LRU cache needs O(1) get and put, so I combine a hash map from key to node with a doubly linked list ordered by recency — move to front on access, evict from the tail when full — using sentinel nodes. In Java, `LinkedHashMap` with access order and `removeEldestEntry` gives it for free; in production I'd use Caffeine, whose W-TinyLFU beats pure LRU and is concurrent.

**Must know:**
* HashMap + doubly linked list; nodes store keys for eviction.
* `LinkedHashMap(cap, lf, true)` + `removeEldestEntry`.
* Thread-safety options; Caffeine W-TinyLFU.
* Scan pollution; approximated LRU in Redis.
* LFU O(1) design.

**Common follow-ups:**
* Make it thread-safe.
* Implement LFU instead.
* Add TTL expiration.

**Red flags:** O(n) list scans to find the LRU entry; forgetting to update recency on `put` of an existing key.
