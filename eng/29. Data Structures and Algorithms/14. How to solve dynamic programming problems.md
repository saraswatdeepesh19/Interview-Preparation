# How to solve dynamic programming problems

---

## 🟢 Junior Level

**Dynamic programming (DP)** solves problems by breaking them into **overlapping subproblems** and **reusing** their answers instead of recomputing them. It applies when:
1. **Optimal substructure** — the best answer is built from best answers to smaller subproblems.
2. **Overlapping subproblems** — the same subproblems appear again and again.

### The classic example: Fibonacci

```java
// Naive recursion: O(2^n) — fib(40) makes ~330 million calls
int fib(int n) { return n < 2 ? n : fib(n - 1) + fib(n - 2); }

// Top-down DP (memoization): O(n)
long fibMemo(int n, long[] memo) {
    if (n < 2) return n;
    if (memo[n] != 0) return memo[n];
    return memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
}

// Bottom-up DP (tabulation) with O(1) space
long fibIter(int n) {
    long a = 0, b = 1;
    for (int i = 0; i < n; i++) { long t = a + b; a = b; b = t; }
    return a;
}
```

### A five-step recipe
1. **Define the state**: what does `dp[i]` (or `dp[i][j]`) mean, in words?
2. **Write the recurrence**: how does a state depend on smaller ones?
3. **Base cases**.
4. **Order of computation** (bottom-up) or memoization (top-down).
5. **Answer location** and **space optimization**.

## 🟡 Middle Level

### 1D DP: climbing stairs / house robber

```java
// House robber: max sum of non-adjacent elements
// dp[i] = max(dp[i-1], dp[i-2] + nums[i])
int rob(int[] nums) {
    int prev2 = 0, prev1 = 0;
    for (int x : nums) {
        int cur = Math.max(prev1, prev2 + x);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
```

### Coin change (unbounded knapsack)

```java
// Minimum coins to make amount; dp[a] = min over coins c of dp[a - c] + 1
int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);            // "infinity"
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins)
            if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
```

Greedy (always take the largest coin) fails for coins `{1, 3, 4}` and amount 6 (greedy: 4+1+1 = 3 coins; optimal: 3+3 = 2) — a classic reason DP is needed.

### 2D DP: longest common subsequence

```java
// dp[i][j] = LCS length of a[0..i) and b[0..j)
int lcs(String a, String b) {
    int[][] dp = new int[a.length() + 1][b.length() + 1];
    for (int i = 1; i <= a.length(); i++)
        for (int j = 1; j <= b.length(); j++)
            dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
                    ? dp[i - 1][j - 1] + 1
                    : Math.max(dp[i - 1][j], dp[i][j - 1]);
    return dp[a.length()][b.length()];
}
```

Related: edit distance (Levenshtein, used in fuzzy search and `git diff`-like tools), unique paths in a grid, longest palindromic subsequence.

## 🔴 Senior Level

### Recognizing DP patterns

| Pattern | State | Examples |
| --- | --- | --- |
| Linear | `dp[i]` = best for prefix/suffix | Climbing stairs, house robber, max subarray (Kadane) |
| 0/1 knapsack | `dp[i][w]` items × capacity (1D reversed loop) | Subset sum, partition equal subset |
| Unbounded knapsack | `dp[w]` forward loop | Coin change, rod cutting |
| Two sequences | `dp[i][j]` | LCS, edit distance, regex/wildcard matching |
| Intervals | `dp[l][r]` | Burst balloons, matrix chain multiplication, palindromes |
| Grid | `dp[r][c]` | Unique paths, minimum path sum |
| Bitmask | `dp[mask][i]` | Traveling salesman (n ≤ 20), assignment |
| Trees | DP returned from children | House robber III, tree diameter |
| LIS | `dp[i]` or patience sorting O(n log n) | Longest increasing subsequence |

### 0/1 knapsack space optimization (iterate backwards!)

```java
// Can we pick a subset summing to target? Each number used at most once.
boolean subsetSum(int[] nums, int target) {
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;
    for (int x : nums)
        for (int s = target; s >= x; s--)        // backwards so x isn't reused in the same round
            dp[s] |= dp[s - x];
    return dp[target];
}
```

Iterating forwards turns it into the unbounded variant — a subtle, frequently tested distinction.

### Longest increasing subsequence in O(n log n)

```java
int lengthOfLIS(int[] nums) {
    int[] tails = new int[nums.length];          // tails[k] = smallest tail of an increasing subsequence of length k+1
    int size = 0;
    for (int x : nums) {
        int i = Arrays.binarySearch(tails, 0, size, x);
        if (i < 0) i = -(i + 1);                 // insertion point
        tails[i] = x;
        if (i == size) size++;
    }
    return size;
}
```

### Top-down vs bottom-up in Java
* Top-down memoization is easier to write from the recurrence and computes only reachable states, but recursion depth can overflow the stack (n ~ 10⁴–10⁵) and `HashMap` memo keys box values.
* Bottom-up avoids recursion, enables rolling arrays (O(n) → O(1) space), and is usually faster due to array locality.
* Reconstructing the actual solution (not just its value) requires keeping the table or parent pointers.

### Real-world DP
Text diffing (Myers' algorithm is an optimized shortest-edit-script), spell correction (edit distance), sequence alignment in bioinformatics, query optimizers choosing join orders (Selinger-style DP over subsets of tables), and dynamic pricing/inventory models.

## 🎯 Interview Cheat Sheet

**30-second pitch:** DP applies when a problem has optimal substructure and overlapping subproblems. I define the state in words, derive the recurrence, set base cases, then implement top-down with memoization or bottom-up with tabulation, and finally optimize space with rolling arrays. I recognize common families: linear, knapsack, two-sequence, interval, grid, bitmask and tree DP.

**Must know:**
* Memoization vs tabulation trade-offs.
* Coin change and why greedy fails.
* LCS / edit distance 2D tables.
* 0/1 knapsack backwards loop vs unbounded forwards.
* LIS in O(n log n).

**Common follow-ups:**
* How do you reconstruct the chosen items?
* What's the time/space complexity of your table?
* Can you reduce space to O(n)?

**Red flags:** jumping to code without defining the state; exponential recursion without memoization; confusing 0/1 and unbounded loops.
