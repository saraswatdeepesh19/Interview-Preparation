# How to solve hashing problems like two-sum and anagrams

---

## 🟢 Junior Level

A **hash table** maps a key to a bucket using a hash function, giving **average O(1)** insert, lookup, and delete. In Java the workhorses are `HashMap<K,V>` and `HashSet<E>`. Hashing problems usually ask: "have I seen this before?", "how many times?", or "what is its complement?".

### Real-world analogy
A coat-check: you hand over a ticket number (hash) and the attendant goes straight to the right hook instead of searching every coat.

### Two-sum
Given `nums` and `target`, return indices of two numbers adding to `target`.

- **Brute force**: check every pair — `O(n²)` time, `O(1)` space.
- **Hash map**: for each `x`, look for `target - x` among previously seen numbers — `O(n)` time, `O(n)` space.

```java
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

public class TwoSum {

    static int[] bruteForce(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++)
            for (int j = i + 1; j < nums.length; j++)
                if (nums[i] + nums[j] == target) return new int[]{i, j};
        return new int[0];
    }

    static int[] hashed(int[] nums, int target) {
        Map<Integer, Integer> indexByValue = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            Integer j = indexByValue.get(target - nums[i]);
            if (j != null) return new int[]{j, i};
            indexByValue.put(nums[i], i);       // insert AFTER the check, so an element is not paired with itself
        }
        return new int[0];
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(hashed(new int[]{2, 7, 11, 15}, 9))); // [0, 1]
    }
}
```

### Valid anagram
Two strings are anagrams if they contain the same characters with the same counts.

```java
public class ValidAnagram {
    // O(n) time, O(1) space for lowercase a-z
    static boolean isAnagram(String a, String b) {
        if (a.length() != b.length()) return false;
        int[] counts = new int[26];
        for (int i = 0; i < a.length(); i++) {
            counts[a.charAt(i) - 'a']++;
            counts[b.charAt(i) - 'a']--;
        }
        for (int c : counts) if (c != 0) return false;
        return true;
    }
}
```

## 🟡 Middle Level

### The "complement" and "frequency" idioms
| Problem | Idea | Complexity |
|---|---|---|
| Two-sum | map value → index, look up complement | O(n) |
| Contains duplicate | `HashSet.add` returns false on repeat | O(n) |
| First non-repeating char | count map, then scan | O(n) |
| Group anagrams | canonical key (sorted chars or count signature) | O(n·k) |
| Subarray sum equals K | prefix-sum → count map | O(n) |
| Longest consecutive sequence | set + start-of-run detection | O(n) |

### Group anagrams

```java
import java.util.*;

public class GroupAnagrams {
    // k = max word length. Sorting key: O(n * k log k). Count-signature key: O(n * k).
    static List<List<String>> group(String[] words) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String w : words) {
            int[] c = new int[26];
            for (char ch : w.toCharArray()) c[ch - 'a']++;
            String key = Arrays.toString(c);        // e.g. "[1, 0, 0, ...]" - unambiguous
            groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
        }
        return new ArrayList<>(groups.values());
    }

    public static void main(String[] args) {
        System.out.println(group(new String[]{"eat", "tea", "tan", "ate", "nat", "bat"}));
    }
}
```

### Subarray sum equals K (works with negatives!)
Idea: `sum(i..j) = prefix[j] - prefix[i-1]`. Count how many earlier prefixes equal `prefix[j] - k`.

```java
import java.util.HashMap;
import java.util.Map;

public class SubarraySumK {
    static int count(int[] nums, int k) {
        Map<Integer, Integer> seen = new HashMap<>();
        seen.put(0, 1);                       // empty prefix
        int prefix = 0, result = 0;
        for (int x : nums) {
            prefix += x;
            result += seen.getOrDefault(prefix - k, 0);
            seen.merge(prefix, 1, Integer::sum);
        }
        return result;
    }

    public static void main(String[] args) {
        System.out.println(count(new int[]{1, 1, 1}, 2));      // 2
        System.out.println(count(new int[]{1, -1, 0}, 0));      // 3
    }
}
```

### Longest consecutive sequence in O(n)

```java
import java.util.HashSet;
import java.util.Set;

public class LongestConsecutive {
    static int longest(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) set.add(x);
        int best = 0;
        for (int x : set) {
            if (!set.contains(x - 1)) {            // x begins a run
                int len = 1;
                while (set.contains(x + len)) len++;
                best = Math.max(best, len);
            }
        }
        return best;
    }
}
```
Each element is visited at most twice, so total `O(n)` — despite the inner `while`.

### Common mistakes
- Using a **mutable key** (a `List` or array) in a `HashMap`: arrays use identity `hashCode`, so `map.get(new int[]{1,2})` fails. Convert to `String`, `List.of`, or a record.
- Overriding `equals` without `hashCode` (or vice versa).
- Pairing an element with itself in two-sum.
- Assuming iteration order of `HashMap`; use `LinkedHashMap` or `TreeMap` when order matters.
- Boxing overhead and `NullPointerException` on `map.get(k)` auto-unboxing into `int`.

Internals of `HashMap` (buckets, treeification, resize) are covered in section 4 — here we apply it to problems.

## 🔴 Senior Level

### Collisions and worst cases
Average `O(1)` assumes a uniform hash. Java's `HashMap` spreads hash bits (`h ^ (h >>> 16)`) and treeifies buckets with ≥ 8 collisions (if the table has ≥ 64 slots), giving `O(log n)` worst-case for `Comparable` keys. Attackers can still craft keys (e.g., colliding `String.hashCode`s like `"Aa"` and `"BB"`) to degrade throughput — mitigate with request-size limits and, for untrusted keys, `ConcurrentHashMap`/treeified bins or salted hashing (SipHash in other ecosystems).

### Custom keys with records (Java 16+)

```java
import java.util.HashMap;
import java.util.Map;

public class RecordKeys {
    record Point(int x, int y) { }       // equals/hashCode generated and consistent

    public static void main(String[] args) {
        Map<Point, String> grid = new HashMap<>();
        grid.put(new Point(1, 2), "tree");
        System.out.println(grid.get(new Point(1, 2)));    // tree
    }
}
```

Avoid building string keys like `x + "," + y` in hot loops (allocation); instead pack into a `long`: `((long) x << 32) | (y & 0xFFFFFFFFL)` and use a primitive-keyed map.

### Large-scale hashing problems
1. **Memory**: a `HashMap<Integer,Integer>` costs ~48–64 bytes per entry (node + two boxed values). For 100M entries use primitive maps (fastutil, Koloboke, Eclipse Collections) or sort-based approaches.
2. **Duplicates in huge files**: external hashing — partition by `hash(key) % P` into P files that each fit in RAM, then dedupe each; or a **Bloom filter** for approximate membership (see the dedicated question).
3. **Distributed keys**: use consistent hashing so adding a node moves only ~1/N keys.
4. **Approximate counting**: HyperLogLog (distinct count), Count-Min Sketch (frequency) — `O(1)` memory per sketch, used by Redis `PFADD` and stream analytics.

### Concurrency
`HashMap` is not thread-safe: concurrent resizes could cause lost updates and (pre-Java 8) infinite loops. Use `ConcurrentHashMap` and its atomic operations (`merge`, `compute`, `computeIfAbsent`) rather than check-then-act:

```java
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.LongAdder;

public class WordCounter {
    private final ConcurrentHashMap<String, LongAdder> counts = new ConcurrentHashMap<>();

    void record(String word) {
        counts.computeIfAbsent(word, k -> new LongAdder()).increment();   // contention-friendly
    }

    long get(String word) {
        LongAdder a = counts.get(word);
        return a == null ? 0 : a.sum();
    }
}
```

Never call a mapping function that modifies the same map inside `computeIfAbsent` (may throw `IllegalStateException` or deadlock).

### Diagnostics
- High CPU in `HashMap.getNode`/`TreeNode.find` → poor `hashCode` distribution; log bucket stats via a heap dump (Eclipse MAT) or measure with a quick histogram of `hashCode() & (n-1)`.
- `OutOfMemoryError` with a giant `HashMap$Node[]` → pre-size, switch to primitive collections, or cap with eviction (see the LRU cache question).
- Floating-point keys: `Double.equals` uses bit equality (`NaN` equals `NaN`, `0.0 != -0.0`); avoid doubles as keys.

## 🎯 Interview Cheat Sheet

### 30-Second Elevator Pitch
> "Hash-based problems trade O(n) memory for O(n) time: store what you have seen in a `HashMap` or `HashSet` and answer 'complement', 'duplicate', or 'frequency' questions in O(1) average. Two-sum is one pass with a value-to-index map; anagrams use a canonical key like a 26-count signature; subarray-sum-equals-K uses prefix sums with a count map and works with negatives. I care about key immutability, `equals`/`hashCode`, boxing cost and thread safety."

### Must-Know Bullets
- Two-sum: O(n) time / O(n) space with a map; insert after the lookup.
- Anagram key: sorted chars O(k log k) or int[26] signature O(k).
- Prefix sum + map handles negative numbers.
- Never use arrays or mutable objects as keys.
- `HashMap` worst case O(log n) in Java 8+, not O(n), for comparable keys.

### Common Follow-Up Questions
1. What if the array is sorted? (Two pointers, O(1) space.)
2. What if there are multiple answers or duplicates?
3. What if the data does not fit in memory?
4. How would you make the counter thread-safe?

### Red Flags (DO NOT Say)
- ❌ "HashMap is always O(1)."
- ❌ "I'll use an array as the map key."
- ❌ Forgetting to handle the `target / 2` duplicate case or pairing an element with itself.
