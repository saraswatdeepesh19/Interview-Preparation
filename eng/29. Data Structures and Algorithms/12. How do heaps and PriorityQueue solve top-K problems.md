# How do heaps and PriorityQueue solve top-K problems

---

## 🟢 Junior Level

A **binary heap** is a complete binary tree stored in an array where every parent is ≤ its children (**min-heap**) or ≥ them (**max-heap**). The smallest (or largest) element is always at the root.

| Operation | Cost |
| --- | --- |
| Peek min/max | O(1) |
| Insert (`offer`) | O(log n) — "sift up" |
| Remove min/max (`poll`) | O(log n) — "sift down" |
| Build from n elements | O(n) |

In Java, **`PriorityQueue`** is a min-heap by default:

```java
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());

minHeap.addAll(List.of(5, 1, 8, 3));
minHeap.poll();   // 1
minHeap.peek();   // 3
```

### Top-K largest with a min-heap of size K
Keep the K largest seen so far; the smallest of them sits on top and is evicted when something bigger arrives:

```java
int[] topK(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>(k);       // min-heap
    for (int x : nums) {
        if (heap.size() < k) heap.offer(x);
        else if (x > heap.peek()) { heap.poll(); heap.offer(x); }
    }
    return heap.stream().mapToInt(Integer::intValue).toArray();  // unordered
}
```

Time **O(n log k)**, space **O(k)** — much better than sorting (O(n log n)) when k ≪ n, and it works on **streams** you can't hold in memory.

## 🟡 Middle Level

### Top-K frequent elements

```java
List<String> topKFrequent(String[] words, int k) {
    Map<String, Integer> freq = new HashMap<>();
    for (String w : words) freq.merge(w, 1, Integer::sum);

    // min-heap by frequency; for ties, reverse alphabetical so the "worst" is on top
    PriorityQueue<Map.Entry<String, Integer>> heap = new PriorityQueue<>(
            Comparator.<Map.Entry<String, Integer>>comparingInt(Map.Entry::getValue)
                      .thenComparing(Map.Entry::getKey, Comparator.reverseOrder()));

    for (var e : freq.entrySet()) {
        heap.offer(e);
        if (heap.size() > k) heap.poll();
    }
    List<String> result = new ArrayList<>();
    while (!heap.isEmpty()) result.add(heap.poll().getKey());
    Collections.reverse(result);                     // most frequent first
    return result;
}
```

Alternative: **bucket sort** by frequency in O(n) when frequencies are bounded by n.

### Merge K sorted lists/arrays

```java
ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> heap = new PriorityQueue<>(Comparator.comparingInt(n -> n.val));
    for (ListNode head : lists) if (head != null) heap.offer(head);
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!heap.isEmpty()) {
        ListNode smallest = heap.poll();
        tail.next = smallest; tail = smallest;
        if (smallest.next != null) heap.offer(smallest.next);
    }
    return dummy.next;
}
```

O(N log k) for N total nodes across k lists — the same idea as the merge phase of external sorting and LSM-tree compaction.

### Running median with two heaps

```java
class MedianFinder {
    private final PriorityQueue<Integer> low = new PriorityQueue<>(Comparator.reverseOrder()); // max-heap
    private final PriorityQueue<Integer> high = new PriorityQueue<>();                         // min-heap

    void add(int x) {
        low.offer(x);
        high.offer(low.poll());                       // keep every low ≤ every high
        if (high.size() > low.size()) low.offer(high.poll());   // low may hold one extra
    }

    double median() {
        return low.size() > high.size() ? low.peek() : (low.peek() + high.peek()) / 2.0;
    }
}
```

## 🔴 Senior Level

### Heap internals
Array layout: node `i` has children `2i+1`, `2i+2` and parent `(i-1)/2`. `offer` appends and sifts up; `poll` moves the last element to the root and sifts down. `PriorityQueue(Collection)` heapifies in O(n) (bottom-up), cheaper than n inserts.

Java specifics:
* `PriorityQueue.iterator()` and `toString()` are **not** in priority order.
* `remove(Object)` and `contains` are O(n) — no index map. For "decrease-key" (Dijkstra), push a new entry and skip stale ones when polled (lazy deletion), or use a `TreeSet` of (priority, id).
* Not thread-safe; `PriorityBlockingQueue` is the unbounded concurrent version; `DelayQueue` is a heap ordered by delay (used for scheduling).

### Choosing the approach for top-K

| Approach | Time | Space | When |
| --- | --- | --- | --- |
| Sort | O(n log n) | O(n) | Small data, simplicity |
| Min-heap of size k | O(n log k) | O(k) | Streams, k ≪ n |
| Quickselect | O(n) average, O(n²) worst | O(1) | In-memory array, unordered result OK |
| Bucket/counting | O(n) | O(n) | Bounded integer keys or frequencies |
| Count-Min Sketch + heap | Sublinear memory | Approximate | Heavy hitters over huge streams |

### Distributed top-K
Real systems (trending hashtags, top products): each partition computes a local top-K' (K' > K for safety) with heaps or approximate sketches (Count-Min Sketch, Space-Saving), and an aggregator merges local results. Exact global top-K in one pass needs care because an item can be below every local cutoff but large in total — sketches or a two-round algorithm (Threshold Algorithm) address this. Redis sorted sets (`ZINCRBY`, `ZREVRANGE 0 k-1`) are a pragmatic option for moderate cardinalities.

## 🎯 Interview Cheat Sheet

**30-second pitch:** A binary heap keeps the min or max at the root with O(log n) insert and remove and O(1) peek; Java's `PriorityQueue` is a min-heap. For top-K largest I keep a min-heap of size K — O(n log k) time, O(k) space, works on streams. Heaps also solve merging K sorted lists, running medians with two heaps, scheduling and Dijkstra.

**Must know:**
* Min-heap of size K for K largest (max-heap of size K for K smallest).
* Comparator construction, including tie-breakers.
* Merge K sorted lists in O(N log k).
* Two-heap median.
* Quickselect and bucket sort alternatives; heapify O(n).

**Common follow-ups:**
* Why a min-heap for the K largest?
* How do you decrease a key in `PriorityQueue`?
* How would you compute top-K trending items across many servers?

**Red flags:** sorting a billion items to get the top 10; assuming `PriorityQueue` iteration is ordered.
