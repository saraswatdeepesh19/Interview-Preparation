# How do sorting algorithms work and what does Java use

---

## 🟢 Junior Level

**Sorting** arranges elements in a defined order. It is the foundation of many other tasks: binary search, deduplication, merging, grouping, and finding medians.

### Real-world analogy
Sorting a hand of playing cards: you pick up a card and slide it into the right place among those already sorted — that is **insertion sort**. Dividing a big pile into two halves, sorting each, and merging them is **merge sort**.

### Quick comparison

| Algorithm | Best | Average | Worst | Extra space | Stable |
|---|---|---|---|---|---|
| Bubble sort | O(n) | O(n²) | O(n²) | O(1) | yes |
| Selection sort | O(n²) | O(n²) | O(n²) | O(1) | no |
| Insertion sort | O(n) | O(n²) | O(n²) | O(1) | yes |
| Merge sort | O(n log n) | O(n log n) | O(n log n) | O(n) | yes |
| Quick sort | O(n log n) | O(n log n) | O(n²) | O(log n) | no |
| Heap sort | O(n log n) | O(n log n) | O(n log n) | O(1) | no |
| Counting sort | O(n + k) | O(n + k) | O(n + k) | O(k) | yes (with care) |

**Stable** means equal elements keep their original relative order (important when sorting by one field after another).

### Insertion sort (simple and great for tiny/nearly sorted data)

```java
import java.util.Arrays;

public class InsertionSort {
    static void sort(int[] a) {
        for (int i = 1; i < a.length; i++) {
            int key = a[i];
            int j = i - 1;
            while (j >= 0 && a[j] > key) {
                a[j + 1] = a[j];     // shift larger elements right
                j--;
            }
            a[j + 1] = key;
        }
    }

    public static void main(String[] args) {
        int[] a = {5, 2, 9, 1, 5, 6};
        sort(a);
        System.out.println(Arrays.toString(a)); // [1, 2, 5, 5, 6, 9]
    }
}
```

### In everyday Java you do not write your own sort

```java
import java.util.*;

public class BuiltInSort {
    public static void main(String[] args) {
        int[] nums = {5, 2, 9, 1};
        Arrays.sort(nums);
        List<String> names = new ArrayList<>(List.of("Bob", "alice", "Carl"));
        Collections.sort(names);                                  // natural order
        names.sort(String.CASE_INSENSITIVE_ORDER);                // custom comparator
        System.out.println(Arrays.toString(nums) + " " + names);
    }
}
```

## 🟡 Middle Level

### Merge sort — divide and conquer, stable, O(n log n) always

```java
import java.util.Arrays;

public class MergeSort {
    static void sort(int[] a) {
        if (a.length < 2) return;
        mergeSort(a, new int[a.length], 0, a.length - 1);
    }

    private static void mergeSort(int[] a, int[] tmp, int lo, int hi) {
        if (lo >= hi) return;
        int mid = lo + (hi - lo) / 2;
        mergeSort(a, tmp, lo, mid);
        mergeSort(a, tmp, mid + 1, hi);
        merge(a, tmp, lo, mid, hi);
    }

    private static void merge(int[] a, int[] tmp, int lo, int mid, int hi) {
        System.arraycopy(a, lo, tmp, lo, hi - lo + 1);
        int i = lo, j = mid + 1;
        for (int k = lo; k <= hi; k++) {
            if (i > mid) a[k] = tmp[j++];
            else if (j > hi) a[k] = tmp[i++];
            else if (tmp[j] < tmp[i]) a[k] = tmp[j++];   // strict '<' keeps equal elements in order -> stable
            else a[k] = tmp[i++];
        }
    }

    public static void main(String[] args) {
        int[] a = {38, 27, 43, 3, 9, 82, 10};
        sort(a);
        System.out.println(Arrays.toString(a));
    }
}
```

### Quick sort — in place, fast in practice, unstable

```java
import java.util.concurrent.ThreadLocalRandom;

public class QuickSort {
    static void sort(int[] a) { quick(a, 0, a.length - 1); }

    private static void quick(int[] a, int lo, int hi) {
        while (lo < hi) {
            int p = partition(a, lo, hi);
            // recurse into the smaller side, loop on the larger: stack depth O(log n)
            if (p - lo < hi - p) { quick(a, lo, p - 1); lo = p + 1; }
            else { quick(a, p + 1, hi); hi = p - 1; }
        }
    }

    // Lomuto partition with a random pivot to avoid O(n^2) on sorted input
    private static int partition(int[] a, int lo, int hi) {
        swap(a, ThreadLocalRandom.current().nextInt(lo, hi + 1), hi);
        int pivot = a[hi], i = lo;
        for (int j = lo; j < hi; j++) {
            if (a[j] < pivot) swap(a, i++, j);
        }
        swap(a, i, hi);
        return i;
    }

    private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
}
```
Lomuto degrades on many duplicates (all equal → `O(n²)`); production implementations use 3-way partitioning or dual-pivot schemes.

### Heap sort — O(n log n) worst case, O(1) space

```java
public class HeapSort {
    static void sort(int[] a) {
        int n = a.length;
        for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);   // build max-heap in O(n)
        for (int end = n - 1; end > 0; end--) {
            int t = a[0]; a[0] = a[end]; a[end] = t;               // move max to its final place
            siftDown(a, 0, end);
        }
    }

    private static void siftDown(int[] a, int i, int n) {
        while (true) {
            int l = 2 * i + 1, r = l + 1, largest = i;
            if (l < n && a[l] > a[largest]) largest = l;
            if (r < n && a[r] > a[largest]) largest = r;
            if (largest == i) return;
            int t = a[i]; a[i] = a[largest]; a[largest] = t;
            i = largest;
        }
    }
}
```

### Counting sort — non-comparison, O(n + k)

```java
public class CountingSort {
    // Values must be in [0, k]. Beats O(n log n) when k = O(n), e.g. ages, grades, byte data.
    static int[] sort(int[] a, int k) {
        int[] count = new int[k + 1];
        for (int x : a) count[x]++;
        int idx = 0;
        int[] out = new int[a.length];
        for (int v = 0; v <= k; v++) {
            while (count[v]-- > 0) out[idx++] = v;
        }
        return out;
    }
}
```
This simple version is for plain integers; for sorting objects by an integer key use prefix sums and iterate input right-to-left to keep it stable. Radix sort applies counting sort digit by digit (`O(d·(n + b))`).

### What does Java use?
- **`Arrays.sort(int[]/long[]/double[]/...)` (primitives)**: **Dual-Pivot Quicksort** (Vladimir Yaroslavskiy; refined in JDK 14 with run detection, heap-sort fallback to guarantee `O(n log n)`, and counting sort for `byte/short/char`). Not stable — irrelevant for primitives since equal values are indistinguishable.
- **`Arrays.sort(Object[])`, `Collections.sort`, `List.sort`**: **TimSort** (Tim Peters, from Python) — a stable hybrid of merge sort and insertion sort that detects existing *runs*, uses binary insertion sort for runs shorter than `minrun` (~32–64), and galloping mode when merging. Best case `O(n)` on already sorted data; worst `O(n log n)`; needs up to `O(n/2)` temp space.
- `Arrays.parallelSort` uses fork/join merge sort on chunks (beneficial for roughly > 8192 elements and multiple cores).
- Stability is required for objects because users sort by multiple keys sequentially.

### Common mistakes
- Comparator `(a, b) -> a - b` overflows for large/negative ints; use `Integer.compare(a, b)`.
- Inconsistent comparators violate the contract → `IllegalArgumentException: Comparison method violates its general contract!` from TimSort.
- Assuming `sort` is stable for primitives or for self-written quicksort.
- Sorting `Integer[]` when `int[]` would do (boxing + merge-sort overhead).

## 🔴 Senior Level

### TimSort details and the 2015 bug
TimSort maintains a stack of runs with invariants (`runLen[i-2] > runLen[i-1] + runLen[i]`, `runLen[i-1] > runLen[i]`). In 2015 formal verification (KeY project) found that the invariant was insufficient, which could throw `ArrayIndexOutOfBoundsException` for specially constructed huge inputs; the stack-size constants were fixed in JDK 8/9 (and `-Djava.util.Arrays.useLegacyMergeSort=true` still selects the old merge sort). Lessons: even battle-tested library code has bugs; edge-case proofs matter.

### Multi-key and custom ordering

```java
import java.util.*;

public class MultiKeySort {
    record Employee(String dept, String name, int salary) { }

    public static void main(String[] args) {
        List<Employee> list = new ArrayList<>(List.of(
                new Employee("IT", "Zoe", 5000),
                new Employee("HR", "Ann", 4000),
                new Employee("IT", "Bob", 5000)));

        list.sort(Comparator.comparing(Employee::dept)
                .thenComparing(Employee::salary, Comparator.reverseOrder())
                .thenComparing(Employee::name));

        list.forEach(System.out::println);
    }
}
```

Prefer `Comparator.comparingInt` to avoid boxing; never use subtraction; handle `null` with `Comparator.nullsFirst`.

### Choosing in production
| Situation | Choice |
|---|---|
| General objects, need stability | `List.sort` / TimSort |
| Primitive arrays | `Arrays.sort` (DPQS) |
| Huge arrays, many cores | `Arrays.parallelSort` (measure first) |
| Small integer range | counting/radix sort |
| Data larger than RAM | **external merge sort**: sort chunks that fit memory, write runs, k-way merge with a `PriorityQueue` |
| Only top-K needed | bounded heap `O(n log k)` or quickselect `O(n)` avg |
| Mostly sorted | insertion sort / TimSort `O(n)` |
| Database | `ORDER BY` on indexed column avoids sorting; otherwise filesort/external merge |

### Quickselect — k-th smallest in expected O(n)

```java
import java.util.concurrent.ThreadLocalRandom;

public class QuickSelect {
    // 0-based k; mutates the array. Expected O(n), worst O(n^2) (mitigated by random pivot)
    static int select(int[] a, int k) {
        int lo = 0, hi = a.length - 1;
        while (true) {
            if (lo == hi) return a[lo];
            int p = partition(a, lo, hi);
            if (k == p) return a[p];
            if (k < p) hi = p - 1; else lo = p + 1;
        }
    }

    private static int partition(int[] a, int lo, int hi) {
        int r = ThreadLocalRandom.current().nextInt(lo, hi + 1);
        int t = a[r]; a[r] = a[hi]; a[hi] = t;
        int pivot = a[hi], i = lo;
        for (int j = lo; j < hi; j++) {
            if (a[j] < pivot) { t = a[i]; a[i] = a[j]; a[j] = t; i++; }
        }
        t = a[i]; a[i] = a[hi]; a[hi] = t;
        return i;
    }
}
```

### Performance and diagnostics
- Comparison sorts have an `Ω(n log n)` lower bound (decision tree with `n!` leaves → `log₂(n!) ≈ n log n`); only non-comparison sorts break it by using key structure.
- Cache behaviour: merge sort streams sequentially (prefetch-friendly); quicksort partitions in place (low memory traffic); heap sort jumps around memory and is typically the slowest in practice despite the same Big-O.
- Sorting 1M `Integer` objects is several times slower than 1M `int`s due to pointer chasing; benchmark with JMH, and mind that `Arrays.sort` on a pre-sorted array in a benchmark measures the best case — regenerate input per invocation.
- Comparator contract violations show up as `Comparison method violates its general contract` in production only on certain data volumes (TimSort needs ≥ 32 elements to hit the merge path) — test with large random inputs and NaN doubles (`Double.compare` orders NaN last and `-0.0 < 0.0`).
- Sort in the database when possible; fetching a million rows to sort in the JVM wastes network and heap.

## 🎯 Interview Cheat Sheet

### 30-Second Elevator Pitch
> "Comparison sorts have an O(n log n) lower bound; merge sort is stable with O(n) space, quicksort is in place and fastest on average but unstable with an O(n²) worst case, heap sort guarantees O(n log n) with O(1) space, and counting sort is O(n + k) for small integer ranges. Java uses dual-pivot quicksort for primitive arrays and TimSort — a stable merge/insertion hybrid that exploits existing runs — for objects, so `List.sort` is O(n) on sorted input and stable."

### Must-Know Bullets
- Stable: merge, insertion, TimSort. Unstable: quick, heap, selection.
- `Arrays.sort(int[])` = dual-pivot quicksort; `Collections.sort`/`List.sort` = TimSort.
- Comparator must be consistent; never subtract ints.
- Top-K: heap or quickselect, not a full sort.
- External sort for data larger than memory.

### Common Follow-Up Questions
1. Why does Java use different algorithms for primitives and objects?
2. How would you sort 100 GB with 1 GB of RAM?
3. When would you pick counting/radix sort?
4. How does quicksort's pivot choice affect complexity?
