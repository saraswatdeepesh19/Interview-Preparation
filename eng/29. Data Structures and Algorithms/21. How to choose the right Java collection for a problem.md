# How to choose the right Java collection for a problem

---

## 🟢 Junior Level

Choosing the right collection is often what turns an O(n²) solution into O(n). Start from the **operations you need** most often:

| Need | Collection | Key costs |
| --- | --- | --- |
| Indexed list, append, iterate | `ArrayList` | get O(1), add amortized O(1), insert/remove middle O(n) |
| Fast membership test, no order | `HashSet` | add/contains/remove O(1) average |
| Key → value lookup, no order | `HashMap` | get/put O(1) average |
| Keep insertion order | `LinkedHashMap` / `LinkedHashSet` | O(1) + order |
| Sorted keys, range/floor/ceiling queries | `TreeMap` / `TreeSet` | O(log n) |
| Stack (LIFO) or queue (FIFO) or both ends | `ArrayDeque` | push/pop/offer/poll O(1) |
| Always get the min/max | `PriorityQueue` | offer/poll O(log n), peek O(1) |
| Small fixed set of enum values | `EnumSet` / `EnumMap` | Bit-vector / array fast |
| Immutable constant data | `List.of`, `Set.of`, `Map.of` | Compact, null-hostile |

```java
// O(n²): List.contains inside a loop
List<String> seen = new ArrayList<>();
for (String s : items) if (!seen.contains(s)) seen.add(s);

// O(n): HashSet
Set<String> seenSet = new LinkedHashSet<>(items);   // dedupe and keep order
```

## 🟡 Middle Level

### Collections that are usually the wrong choice
* **`LinkedList`** — O(1) insert at known node, but `get(i)` is O(n) and every element is a separate node object (poor cache locality, ~24+ bytes overhead each). `ArrayDeque` beats it as a queue/stack; `ArrayList` beats it almost everywhere else.
* **`Stack` and `Vector`** — legacy, synchronized on every call; use `ArrayDeque`.
* **`Hashtable`** — legacy synchronized map; use `HashMap` or `ConcurrentHashMap`.

### Map idioms that simplify code

```java
Map<String, Integer> counts = new HashMap<>();
for (String w : words) counts.merge(w, 1, Integer::sum);                 // frequency count

Map<String, List<Order>> byCustomer = new HashMap<>();
for (Order o : orders) byCustomer.computeIfAbsent(o.customerId(), k -> new ArrayList<>()).add(o);  // grouping

int total = counts.getOrDefault("missing", 0);

// Streams equivalents
Map<String, Long> freq = words.stream().collect(Collectors.groupingBy(w -> w, Collectors.counting()));
```

### Sorting and ordering choices
* Need sorted output once → collect into a list and `sort` (O(n log n)).
* Need sorted order **while** inserting and removing → `TreeMap`/`TreeSet`.
* Need only the top element repeatedly → `PriorityQueue` (cheaper than a `TreeSet`, allows duplicates).

### `equals`/`hashCode` and `compareTo` contracts
Hash-based collections require consistent `equals` and `hashCode`; mutable keys that change after insertion get "lost". `TreeSet`/`TreeMap` use `compareTo`/comparator for equality — a comparator that returns 0 for distinct objects silently drops elements:

```java
Set<Person> byAge = new TreeSet<>(Comparator.comparingInt(Person::age));
byAge.add(new Person("Ada", 36));
byAge.add(new Person("Bob", 36));     // NOT added: comparator says equal
// Fix: thenComparing(Person::name) to make the ordering consistent with equals
```

## 🔴 Senior Level

### Performance details that matter at scale
* **Pre-size** hash maps when you know the size: `new HashMap<>(expected)` doesn't do what most people think — the argument is capacity, and resizing happens at 75% load. Java 19+ has `HashMap.newHashMap(expectedSize)` which accounts for the load factor.
* **Boxing**: `Map<Integer, Integer>` and `List<Long>` box every value (16+ bytes per `Integer`, pointer chasing). For hot numeric paths use primitive arrays or primitive collections (Eclipse Collections `IntIntHashMap`, fastutil, HPPC).
* **`ArrayList` growth** is 1.5× — pre-size with `new ArrayList<>(n)` or use `ensureCapacity` for bulk loads.
* **Iteration order of `HashMap`** is unspecified and may change between Java versions — never rely on it in tests or output.
* **Immutable factories** (`List.of`) reject `null` and are compact (special classes for 0–2 elements); `Collections.unmodifiableList` is a view (changes to the underlying list show through); `List.copyOf` copies.

### Concurrency choices

| Need | Collection |
| --- | --- |
| Concurrent map, high throughput | `ConcurrentHashMap` (`compute`, `merge` are atomic per key) |
| Concurrent sorted map | `ConcurrentSkipListMap` |
| Read-mostly list (listeners) | `CopyOnWriteArrayList` |
| Producer-consumer queue | `ArrayBlockingQueue` (bounded), `LinkedBlockingQueue`, `LinkedTransferQueue` |
| Concurrent non-blocking queue | `ConcurrentLinkedQueue` / `ConcurrentLinkedDeque` |
| Delayed tasks | `DelayQueue`, `ScheduledThreadPoolExecutor` |

`Collections.synchronizedMap` serializes every call and still needs external locking for compound operations (check-then-act, iteration).

### Sequenced collections (Java 21)
`SequencedCollection`, `SequencedSet`, `SequencedMap` give uniform `getFirst()`, `getLast()`, `addFirst()`, `reversed()`, `pollFirstEntry()` across `List`, `Deque`, `LinkedHashSet`, `LinkedHashMap`, `TreeMap` — simplifies LRU-style and ordered-access code.

### Interview framing
State the access pattern, then justify: "I need O(1) lookups by ID and to evict the oldest entry, so `LinkedHashMap` with access order; if multiple threads update it, I'd switch to Caffeine rather than synchronizing it."

## 🎯 Interview Cheat Sheet

**30-second pitch:** I pick collections from the dominant operations: `ArrayList` for indexed access, `HashMap`/`HashSet` for O(1) lookup and membership, `LinkedHash*` to keep order, `TreeMap`/`TreeSet` for sorted and range queries, `ArrayDeque` for stacks and queues, `PriorityQueue` for repeated min/max, and `EnumSet`/`EnumMap` for enums. I avoid `LinkedList`, `Stack`, `Vector` and `Hashtable`, watch boxing and sizing at scale, and use `java.util.concurrent` types for concurrency.

**Must know:**
* Big-O of common operations per collection.
* `merge`, `computeIfAbsent`, `getOrDefault` idioms.
* Comparator consistency with equals in `TreeSet`.
* `HashMap.newHashMap(n)`; boxing costs; primitive collections.
* Concurrent collection choices; sequenced collections in Java 21.

**Common follow-ups:**
* Why is `ArrayDeque` preferred over `LinkedList`?
* What happens if you mutate a `HashMap` key?
* When would you use `CopyOnWriteArrayList`?

**Red flags:** `List.contains` in loops; `LinkedList` "for performance"; synchronizing collections and then iterating without a lock.
