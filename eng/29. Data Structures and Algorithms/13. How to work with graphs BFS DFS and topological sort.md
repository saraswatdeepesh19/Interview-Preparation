# How to work with graphs BFS DFS and topological sort

---

## 🟢 Junior Level

A **graph** is a set of **vertices** (nodes) connected by **edges**. Edges can be **directed** (A → B) or **undirected**, and **weighted** or not. Trees are graphs without cycles; grids are graphs where each cell connects to its neighbors.

### Representations
* **Adjacency list** — `Map<Integer, List<Integer>>` or `List<List<Integer>>`; O(V + E) memory. The default for sparse graphs.
* **Adjacency matrix** — `boolean[V][V]`; O(V²) memory, O(1) edge lookup. Only for dense or small graphs.

```java
List<List<Integer>> buildGraph(int n, int[][] edges, boolean directed) {
    List<List<Integer>> g = new ArrayList<>(n);
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    for (int[] e : edges) {
        g.get(e[0]).add(e[1]);
        if (!directed) g.get(e[1]).add(e[0]);
    }
    return g;
}
```

### BFS and DFS
Same idea as for trees, plus a **visited** set because graphs can have cycles:

```java
// BFS: shortest path length (in edges) in an unweighted graph
int shortestPath(List<List<Integer>> g, int start, int target) {
    int[] dist = new int[g.size()];
    Arrays.fill(dist, -1);
    Deque<Integer> queue = new ArrayDeque<>();
    queue.offer(start);
    dist[start] = 0;
    while (!queue.isEmpty()) {
        int u = queue.poll();
        if (u == target) return dist[u];
        for (int v : g.get(u)) {
            if (dist[v] == -1) { dist[v] = dist[u] + 1; queue.offer(v); }   // mark when enqueued
        }
    }
    return -1;
}

// DFS: count connected components
int components(List<List<Integer>> g) {
    boolean[] seen = new boolean[g.size()];
    int count = 0;
    for (int i = 0; i < g.size(); i++) {
        if (!seen[i]) { count++; dfs(g, i, seen); }
    }
    return count;
}
void dfs(List<List<Integer>> g, int u, boolean[] seen) {
    seen[u] = true;
    for (int v : g.get(u)) if (!seen[v]) dfs(g, v, seen);
}
```

Both are **O(V + E)**.

## 🟡 Middle Level

### Topological sort (Kahn's algorithm)
Orders the vertices of a **directed acyclic graph (DAG)** so every edge goes from earlier to later — build order, course prerequisites, task scheduling, Spring bean initialization order, database migration dependencies.

```java
// Returns an order, or an empty list if there's a cycle
List<Integer> topoSort(int n, int[][] edges) {          // edge {a, b} means a must come before b
    List<List<Integer>> g = buildGraph(n, edges, true);
    int[] indegree = new int[n];
    for (int[] e : edges) indegree[e[1]]++;

    Deque<Integer> ready = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indegree[i] == 0) ready.offer(i);

    List<Integer> order = new ArrayList<>(n);
    while (!ready.isEmpty()) {
        int u = ready.poll();
        order.add(u);
        for (int v : g.get(u)) if (--indegree[v] == 0) ready.offer(v);
    }
    return order.size() == n ? order : List.of();       // leftover nodes => cycle
}
```

### Cycle detection in directed graphs (DFS with colors)

```java
// 0 = unvisited, 1 = on current path, 2 = done
boolean hasCycle(List<List<Integer>> g) {
    int[] state = new int[g.size()];
    for (int i = 0; i < g.size(); i++) if (state[i] == 0 && dfsCycle(g, i, state)) return true;
    return false;
}
boolean dfsCycle(List<List<Integer>> g, int u, int[] state) {
    state[u] = 1;
    for (int v : g.get(u)) {
        if (state[v] == 1) return true;                  // back edge
        if (state[v] == 0 && dfsCycle(g, v, state)) return true;
    }
    state[u] = 2;
    return false;
}
```

### Grids are graphs

```java
int numIslands(char[][] grid) {
    int count = 0;
    for (int r = 0; r < grid.length; r++)
        for (int c = 0; c < grid[0].length; c++)
            if (grid[r][c] == '1') { count++; sink(grid, r, c); }
    return count;
}
void sink(char[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != '1') return;
    g[r][c] = '0';
    sink(g, r + 1, c); sink(g, r - 1, c); sink(g, r, c + 1); sink(g, r, c - 1);
}
```

## 🔴 Senior Level

### Weighted shortest paths

| Algorithm | Handles | Complexity | Notes |
| --- | --- | --- | --- |
| BFS | Unweighted | O(V + E) | |
| 0-1 BFS | Weights 0/1 | O(V + E) | Deque: push 0-edges front |
| **Dijkstra** | Non-negative weights | O((V + E) log V) with a heap | Lazy deletion with `PriorityQueue` |
| Bellman-Ford | Negative weights, detects negative cycles | O(V·E) | |
| Floyd-Warshall | All pairs | O(V³) | Small V |
| A* | Non-negative + heuristic | Often much faster than Dijkstra | Routing, games |

```java
int[] dijkstra(List<List<int[]>> g, int src) {             // g.get(u) = list of {v, weight}
    int[] dist = new int[g.size()];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[1]));
    pq.offer(new int[]{src, 0});
    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int u = cur[0], d = cur[1];
        if (d > dist[u]) continue;                           // stale entry (lazy deletion)
        for (int[] e : g.get(u)) {
            int v = e[0], nd = d + e[1];
            if (nd < dist[v]) { dist[v] = nd; pq.offer(new int[]{v, nd}); }
        }
    }
    return dist;
}
```

### Union-Find (disjoint set union)
For dynamic connectivity, cycle detection in undirected graphs, and Kruskal's minimum spanning tree — nearly O(1) amortized per operation with path compression and union by rank:

```java
int[] parent, rank;
int find(int x) { return parent[x] == x ? x : (parent[x] = find(parent[x])); }
boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;                      // already connected => adding edge forms a cycle
    if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
    parent[rb] = ra;
    if (rank[ra] == rank[rb]) rank[ra]++;
    return true;
}
```

### Backend relevance
* Dependency resolution (Maven, Spring context, migrations) = topological sort + cycle detection (Spring's `BeanCurrentlyInCreationException` is a cycle report).
* Deadlock detection = cycle in the wait-for graph (databases do this).
* Service call graphs, network routing, fraud rings, recommendation "friends of friends" — BFS/DFS at scale move to graph databases or distributed graph processing (Pregel-style).
* Recursion depth: DFS on 10⁶ nodes overflows the stack — use an explicit stack.

## 🎯 Interview Cheat Sheet

**30-second pitch:** I represent sparse graphs as adjacency lists, use BFS with a visited set for shortest paths in unweighted graphs and DFS for connectivity and cycle detection, both O(V + E). Topological sort with Kahn's indegree algorithm orders DAGs and detects cycles; Dijkstra with a priority queue handles non-negative weights; Union-Find handles dynamic connectivity.

**Must know:**
* Adjacency list vs matrix.
* Mark visited when enqueuing in BFS.
* Kahn's algorithm; DFS three-color cycle detection.
* Dijkstra with lazy deletion; Bellman-Ford for negative weights.
* Union-Find with path compression and union by rank.

**Common follow-ups:**
* Course schedule: can all courses be finished?
* Shortest path in a grid with obstacles?
* How does Spring detect circular dependencies?

**Red flags:** forgetting the visited set; recursive DFS on huge graphs; Dijkstra with negative edges.
