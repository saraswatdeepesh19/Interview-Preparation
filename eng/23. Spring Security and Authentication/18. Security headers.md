# Security headers

---

## 🟢 Junior Level

**Security headers** are HTTP response headers that tell the browser to enable protections. They cost almost nothing and close whole classes of attacks. Spring Security adds a safe set by default:

```http
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Pragma: no-cache
Expires: 0
Strict-Transport-Security: max-age=31536000 ; includeSubDomains      (HTTPS requests only)
X-XSS-Protection: 0
```

| Header | Protects against |
| --- | --- |
| `Strict-Transport-Security` (HSTS) | Downgrade to HTTP, SSL stripping |
| `Content-Security-Policy` (CSP) | XSS, data injection, clickjacking (`frame-ancestors`) |
| `X-Frame-Options` | Clickjacking (legacy; CSP `frame-ancestors` supersedes it) |
| `X-Content-Type-Options: nosniff` | MIME sniffing (browser treating JSON/text as HTML/JS) |
| `Referrer-Policy` | Leaking URLs (with tokens or IDs) to other sites |
| `Permissions-Policy` | Unwanted use of camera, microphone, geolocation |
| `Cache-Control: no-store` | Sensitive responses stored in shared/browser caches |

## 🟡 Middle Level

### Configuring headers in Spring Security

```java
@Bean
SecurityFilterChain web(HttpSecurity http) throws Exception {
    return http
        .headers(h -> h
            .httpStrictTransportSecurity(hsts -> hsts.maxAgeInSeconds(31_536_000).includeSubDomains(true).preload(true))
            .contentSecurityPolicy(csp -> csp.policyDirectives(
                "default-src 'self'; img-src 'self' data: https://cdn.shop.com; " +
                "script-src 'self'; style-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; " +
                "form-action 'self'; upgrade-insecure-requests"))
            .referrerPolicy(r -> r.policy(ReferrerPolicyHeaderWriter.ReferrerPolicy.STRICT_ORIGIN_WHEN_CROSS_ORIGIN))
            .permissionsPolicyHeader(p -> p.policy("camera=(), microphone=(), geolocation=()"))
            .frameOptions(HeadersConfigurer.FrameOptionsConfig::deny))
        .authorizeHttpRequests(a -> a.anyRequest().authenticated())
        .build();
}
```

### Why `X-XSS-Protection: 0`?
The old browser XSS auditor was removed from Chrome and Edge because it could itself be abused to leak data; OWASP now recommends disabling it and relying on CSP. Spring Security 6 sends `0` by default.

### HSTS details
* Sent only over HTTPS (browsers ignore it over HTTP).
* `includeSubDomains` affects every subdomain — make sure all of them support HTTPS first.
* `preload` + submission to hstspreload.org bakes the domain into browsers; removal takes months. Start with a small `max-age` (e.g. 300) and increase.

### APIs vs web pages
JSON APIs benefit mainly from `nosniff`, `Cache-Control: no-store` on sensitive data, HSTS, and a strict `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'` (an API response should never execute anything or be framed). CSP matters most for HTML pages.

## 🔴 Senior Level

### CSP that actually stops XSS
Allow-list CSPs (`script-src 'self' https://cdn.x.com`) are often bypassable through JSONP endpoints or script gadgets hosted on allowed domains. Google's recommended approach is a **strict CSP** with nonces:

```
Content-Security-Policy: script-src 'nonce-R4nd0m' 'strict-dynamic'; object-src 'none'; base-uri 'none';
```

* Each response gets a fresh, unpredictable nonce; only `<script nonce="R4nd0m">` tags run.
* `'strict-dynamic'` lets those trusted scripts load further scripts (bundler chunks) without listing hosts.
* Implement with a `OncePerRequestFilter` generating `Base64(SecureRandom 16 bytes)`, exposing it as a request attribute for templates, and setting the header — or use the nonce support in your web framework.

### Roll out with report-only
Deploy as `Content-Security-Policy-Report-Only` first with `report-to` (Reporting API) or `report-uri`, collect violations for a few weeks, fix inline handlers (`onclick=`), inline styles and third-party scripts, then enforce. CSP violations from browser extensions are noisy — filter them in your collector.

### Cross-origin isolation headers
* `Cross-Origin-Opener-Policy: same-origin` — isolates your window from cross-origin popups (mitigates XS-Leaks and Spectre-class attacks).
* `Cross-Origin-Resource-Policy: same-origin` — prevents other sites from embedding your resources (`<img>`, `<script>`) to probe them.
* `Cross-Origin-Embedder-Policy: require-corp` — together with COOP enables `crossOriginIsolated` (needed for `SharedArrayBuffer`).

### Where to set headers
* **Application** (Spring) — knows context (e.g. nonce, per-route caching), tested with the code.
* **Edge** (CDN, ingress, API gateway) — consistent for all services, including static assets and error pages generated by the proxy.
Pick one owner per header to avoid duplicates and conflicting values (two CSP headers are *both* enforced, intersecting their policies). Verify in CI with a test:

```java
mvc.perform(get("/"))
   .andExpect(header().string("X-Content-Type-Options", "nosniff"))
   .andExpect(header().string("Content-Security-Policy", containsString("frame-ancestors 'none'")));
```

and in production with scanners (Mozilla Observatory, securityheaders.com) on every release.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Security headers instruct browsers to enable protections: HSTS forces HTTPS, CSP restricts what scripts and frames may run, nosniff stops MIME confusion, frame-ancestors/X-Frame-Options stop clickjacking, Referrer-Policy and Permissions-Policy limit leakage, and no-store keeps sensitive data out of caches. Spring Security sets good defaults; CSP needs a deliberate, nonce-based policy rolled out in report-only mode first.

**Must know:**
* Spring defaults: nosniff, X-Frame-Options DENY, no-cache, HSTS on HTTPS, X-XSS-Protection 0.
* HSTS `includeSubDomains` and `preload` implications.
* Strict CSP: nonces + `strict-dynamic`; `Report-Only` rollout.
* COOP/CORP/COEP for cross-origin isolation.
* One owner per header (app vs edge).

**Common follow-ups:**
* Why is `X-XSS-Protection` disabled?
* How do you add CSP to an app with inline scripts?
* Which headers matter for a pure JSON API?

**Red flags:** `unsafe-inline` + `unsafe-eval` CSP that allows everything; enabling HSTS preload without checking subdomains.
