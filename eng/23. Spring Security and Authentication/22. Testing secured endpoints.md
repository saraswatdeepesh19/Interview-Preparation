# Testing secured endpoints

---

## 🟢 Junior Level

Security rules are code, and they break like code: a new endpoint without a rule, a refactored matcher, a role renamed. Tests should prove three things for each endpoint:

1. **Unauthenticated** requests are rejected (`401`).
2. **Authenticated but unauthorized** requests are rejected (`403`, or `404` for hidden resources).
3. **Authorized** requests succeed.

`spring-security-test` provides helpers for MockMvc and method security.

```java
@WebMvcTest(AdminController.class)
@Import(SecurityConfig.class)                  // test the real security rules
class AdminControllerSecurityTest {
    @Autowired MockMvc mvc;
    @MockitoBean AdminService admin;

    @Test
    void anonymousIsRejected() throws Exception {
        mvc.perform(get("/admin/users")).andExpect(status().isUnauthorized());
    }

    @Test
    @WithMockUser(roles = "USER")
    void regularUserIsForbidden() throws Exception {
        mvc.perform(get("/admin/users")).andExpect(status().isForbidden());
    }

    @Test
    @WithMockUser(roles = "ADMIN")
    void adminCanList() throws Exception {
        mvc.perform(get("/admin/users")).andExpect(status().isOk());
    }
}
```

## 🟡 Middle Level

### JWT resource servers

```java
@Test
void requiresOrdersReadScope() throws Exception {
    mvc.perform(get("/api/orders/42")
            .with(jwt().jwt(j -> j.subject("user-7").claim("tenant", "acme"))
                       .authorities(new SimpleGrantedAuthority("SCOPE_orders:read"))))
       .andExpect(status().isOk());

    mvc.perform(get("/api/orders/42")
            .with(jwt().authorities(new SimpleGrantedAuthority("SCOPE_profile"))))
       .andExpect(status().isForbidden());
}
```

`jwt()` builds a `JwtAuthenticationToken` without contacting the IdP. Note: `.authorities(...)` **replaces** what your `JwtAuthenticationConverter` would derive from claims — to test the converter itself, set claims (`.jwt(j -> j.claim("scope", "orders:read"))`) and let the converter map them, or unit-test the converter separately.

### CSRF in tests
For session-based apps with CSRF enabled, state-changing requests need a token:

```java
mvc.perform(post("/profile").with(csrf()).with(user("ada")).param("name", "Ada L."))
   .andExpect(status().is3xxRedirection());

mvc.perform(post("/profile").with(user("ada")).param("name", "x"))   // no token
   .andExpect(status().isForbidden());
```

### Method security
`@PreAuthorize` on services is tested without MVC:

```java
@SpringJUnitConfig(MethodSecurityTestConfig.class)   // @EnableMethodSecurity + the service bean
class InvoiceServiceSecurityTest {
    @Autowired InvoiceService invoices;

    @Test
    @WithMockUser(username = "ada", authorities = "invoice:read")
    void ownerCanRead() { assertThatCode(() -> invoices.find(ADA_INVOICE)).doesNotThrowAnyException(); }

    @Test
    @WithMockUser(username = "bob", authorities = "invoice:read")
    void otherUserCannotRead() {
        assertThatThrownBy(() -> invoices.find(ADA_INVOICE)).isInstanceOf(AccessDeniedException.class);
    }
}
```

For custom principals, write a `@WithSecurityContext` annotation (e.g. `@WithCustomer(id = "c-1", tier = PREMIUM)`) backed by a `WithSecurityContextFactory`.

## 🔴 Senior Level

### An access-control matrix test
Most authorization regressions are *missing* rules on new endpoints. Generate tests from the actual handler mappings so new endpoints can't slip through:

```java
@SpringBootTest @AutoConfigureMockMvc
class AccessMatrixTest {
    @Autowired MockMvc mvc;
    @Autowired RequestMappingHandlerMapping mappings;

    static final Map<String, Set<String>> ALLOWED = Map.of(          // endpoint pattern -> roles
        "GET /api/orders/{id}", Set.of("CUSTOMER", "SUPPORT"),
        "POST /api/refunds",    Set.of("SUPPORT"),
        "GET /admin/users",     Set.of("ADMIN"));

    @TestFactory
    Stream<DynamicTest> everyEndpointHasAnExplicitPolicy() {
        return mappings.getHandlerMethods().keySet().stream()
            .flatMap(info -> endpoints(info))                       // "GET /api/orders/{id}", ...
            .map(ep -> DynamicTest.dynamicTest(ep, () -> {
                assertThat(ALLOWED).as("no policy declared for " + ep).containsKey(ep);
                for (String role : ALL_ROLES) {
                    int status = call(ep, role);
                    if (ALLOWED.get(ep).contains(role)) assertThat(status).isNotIn(401, 403);
                    else assertThat(status).isIn(403, 404);
                }
            }));
    }
}
```

Combined with `anyRequest().denyAll()` as the last rule (instead of `authenticated()`), forgetting a rule fails closed *and* fails a test.

### End-to-end with a real IdP
Unit-level mocks don't verify signature validation, issuer/audience checks, clock skew or JWKS rotation. Add a few integration tests with a real token issuer:
* **Keycloak in Testcontainers** (`dasniko/testcontainers-keycloak`): import a realm, obtain tokens with the password or client-credentials grant, call your app over HTTP.
* Or a **local signing key**: generate an RSA key in the test, configure `spring.security.oauth2.resourceserver.jwt.public-key-location`, mint tokens with Nimbus — tests for expired tokens, wrong `aud`, wrong `iss`, `alg: none`, and tampered signatures must all yield 401.

```java
JWTClaimsSet claims = new JWTClaimsSet.Builder()
        .issuer("https://test-issuer").audience("order-service")
        .subject("user-7").claim("scope", "orders:read")
        .expirationTime(Date.from(Instant.now().minusSeconds(60)))      // already expired
        .build();
SignedJWT jwt = new SignedJWT(new JWSHeader.Builder(JWSAlgorithm.RS256).keyID("test").build(), claims);
jwt.sign(new RSASSASigner(privateKey));

given().auth().oauth2(jwt.serialize())
       .when().get("/api/orders/42")
       .then().statusCode(401);                                        // expired => rejected
```

### Security regression suite in CI
* **DAST**: OWASP ZAP baseline/API scan against the deployed test environment using the OpenAPI spec.
* **Header checks**: assert CSP, HSTS, nosniff on representative responses.
* **Negative tests per bug**: every security incident gets a test that reproduces it.

## 🎯 Interview Cheat Sheet

**30-second pitch:** For every endpoint I test unauthenticated (401), unauthorized (403/404) and authorized cases with `spring-security-test` — `@WithMockUser`, `jwt()`, `csrf()` — and I test method security directly on services. To catch missing rules I generate an access-control matrix from the handler mappings with deny-by-default, and I keep a few integration tests with real signed tokens to verify signature, issuer, audience and expiry checks.

**Must know:**
* `@WithMockUser`, `user()`, `jwt()`, `opaqueToken()`, `csrf()` post-processors.
* `jwt().authorities()` bypasses your converter.
* `@WithSecurityContext` for custom principals.
* Deny-by-default + matrix test for new endpoints.
* Keycloak Testcontainers or locally signed JWTs for real validation tests.

**Common follow-ups:**
* How do you test a custom `JwtAuthenticationConverter`?
* Why does my POST test return 403?
* How do you make sure new endpoints are secured?

**Red flags:** disabling security in tests (`@AutoConfigureMockMvc(addFilters = false)`) for all controller tests; only testing happy paths.
