# How to build an OAuth 2.0 Resource Server

---

## 🟢 Junior Level

### 1. Definition

A **Resource Server** is an API that accepts **access tokens** instead of passwords. It does not log users in; it only checks that the presented token is valid and what it permits. The tokens come from an authorization server (Keycloak, Okta, Spring Authorization Server).

### 2. Analogy

A concert gate scanner: it doesn't sell tickets (authorization server does), it only checks that your ticket is genuine, not expired, and valid for this show.

### 3. Minimal Setup

Dependencies: `spring-boot-starter-web`, `spring-boot-starter-oauth2-resource-server`.

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://sso.example.com/realms/company
```

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class ResourceServerConfig {

    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        return http
            .authorizeHttpRequests(a -> a
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/orders/**").hasAuthority("SCOPE_orders.read")
                .anyRequest().authenticated())
            .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults()))
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .csrf(c -> c.disable())
            .build();
    }
}
```

Call it: `curl -H "Authorization: Bearer <token>" http://localhost:8080/orders`.

## 🟡 Middle Level

### 1. What Spring Does on Startup and per Request

1. At startup, with `issuer-uri`, it calls `/.well-known/openid-configuration` (lazily on first request in recent versions) to find `jwks_uri`, then builds a `NimbusJwtDecoder`.
2. `BearerTokenAuthenticationFilter` extracts the token via `DefaultBearerTokenResolver` (header `Authorization: Bearer`).
3. `JwtAuthenticationProvider` decodes/validates; `JwtAuthenticationConverter` maps claims to authorities (default `SCOPE_` + each value of `scope`/`scp`).
4. Result: `JwtAuthenticationToken` in the context; principal is a `Jwt`.
5. Failure: `BearerTokenAuthenticationEntryPoint` -> `401` with `WWW-Authenticate`; insufficient scope -> `403` with `error="insufficient_scope"`.

### 2. Mapping Roles from Claims (Keycloak example)

```java
@Bean
JwtAuthenticationConverter jwtAuthenticationConverter() {
    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    converter.setJwtGrantedAuthoritiesConverter(jwt -> {
        Collection<GrantedAuthority> authorities = new ArrayList<>(new JwtGrantedAuthoritiesConverter().convert(jwt));
        Map<String, Object> realm = jwt.getClaim("realm_access");
        if (realm != null && realm.get("roles") instanceof Collection<?> roles) {
            roles.forEach(r -> authorities.add(new SimpleGrantedAuthority("ROLE_" + r)));
        }
        return authorities;
    });
    converter.setPrincipalClaimName("preferred_username");
    return converter;
}
// .oauth2ResourceServer(o -> o.jwt(j -> j.jwtAuthenticationConverter(jwtAuthenticationConverter())))
```

### 3. Validating the Audience

`issuer-uri` validates only `iss`, `exp`, `nbf`. Add `aud` check, otherwise a token issued to *another API* by the same IdP is accepted:

```java
@Bean
JwtDecoder jwtDecoder(@Value("${spring.security.oauth2.resourceserver.jwt.issuer-uri}") String issuer) {
    NimbusJwtDecoder decoder = JwtDecoders.fromIssuerLocation(issuer);
    OAuth2TokenValidator<Jwt> audience = new JwtClaimValidator<List<String>>("aud", aud -> aud != null && aud.contains("orders-api"));
    decoder.setJwtValidator(new DelegatingOAuth2TokenValidator<>(JwtValidators.createDefaultWithIssuer(issuer), audience));
    return decoder;
}
```

Newer Boot supports `spring.security.oauth2.resourceserver.jwt.audiences: orders-api`.

### 4. Opaque Tokens vs JWT

| | JWT (local validation) | Opaque (introspection) |
| :--- | :--- | :--- |
| Validation | Signature check, no network per call | HTTP call to IdP (cache!) |
| Revocation | Delayed until `exp` | Immediate |
| Config | `jwt.issuer-uri` / `jwk-set-uri` | `opaquetoken.introspection-uri` + client creds |

### 5. Using the Principal

```java
@GetMapping("/orders")
List<Order> mine(@AuthenticationPrincipal Jwt jwt) {
    return orders.findByOwner(jwt.getSubject());
}
```

### 6. Common Mistakes

- Forgetting `csrf.disable()` for a stateless API -> every POST returns 403 (CSRF is safe to disable only when no cookies authenticate).
- Wrong authority prefix: scope `orders.read` becomes `SCOPE_orders.read`, not `orders.read`.
- Relying on `issuer-uri` when the IdP is unreachable at boot (Spring 6 delays discovery; use `jwk-set-uri` to avoid dependency).
- Trusting claims such as `email` without `email_verified`.
- Returning HTML error pages to API clients.

## 🔴 Senior Level

### 1. JWKS Handling and Resilience

`NimbusJwtDecoder.withJwkSetUri(...)` uses a cached `RemoteJWKSet` (default TTL 5 min, refresh on unknown `kid` rate-limited). If the IdP is down, cached keys keep working. Add a custom `RestOperations` with timeouts (connect 2 s / read 2 s) and an alert on JWKS fetch failures; otherwise a stuck HTTP call blocks request threads.

```java
@Bean
JwtDecoder decoder(RestTemplateBuilder builder) {
    RestTemplate rest = builder.setConnectTimeout(Duration.ofSeconds(2)).setReadTimeout(Duration.ofSeconds(2)).build();
    return NimbusJwtDecoder.withJwkSetUri("https://sso.example.com/realms/company/protocol/openid-connect/certs")
            .restOperations(rest)
            .jwsAlgorithm(SignatureAlgorithm.RS256)      // pin algorithm
            .build();
}
```

### 2. Multi-Tenancy

`JwtIssuerAuthenticationManagerResolver` supports many issuers from an allow-list; resolver caches an `AuthenticationManager` per issuer. Never use unconstrained dynamic issuers.

### 3. Custom Error Responses

```java
.oauth2ResourceServer(o -> o
    .jwt(Customizer.withDefaults())
    .authenticationEntryPoint((req, res, ex) -> {
        res.setStatus(401);
        res.setContentType("application/problem+json");
        res.getWriter().write("{\"type\":\"about:blank\",\"title\":\"Unauthorized\",\"status\":401}");
    })
    .accessDeniedHandler((req, res, ex) -> res.sendError(403)))
```

Don't leak validation details (`Jwt expired at ...` is acceptable; stack traces are not).

### 4. Performance

Local JWT validation is typically < 0.1 ms. Introspection adds an RTT per request: use `CachingOpaqueTokenIntrospector`-style caching (short TTL), or move validation to the **API gateway** and pass a trusted internal token downstream. Authority loading from a DB per request defeats statelessness; keep roles in claims or cache them.

### 5. Verification Beyond Basics

- **Scope vs resource-level authz:** scopes say "client may read orders"; still check `jwt.getSubject()` owns the order.
- **Sender-constrained tokens (DPoP/mTLS)**: validate `cnf` in a custom `OAuth2TokenValidator`.
- **Token size**: if the JWT exceeds 8 KB, ingress rejects with 431/400 - trim claims.
- **Clock skew**: `JwtTimestampValidator(Duration.ofSeconds(30))`.

### 6. Observability

Log `iss`, `sub`, `client_id` (`azp`) and `jti` (never the token) in MDC from an `AuthenticationSuccessEvent` listener; count 401/403 per reason; sample failures for anomaly detection.

## 🎯 Interview Cheat Sheet

### 30-Second Elevator Pitch
A resource server is a stateless API protected by `oauth2ResourceServer()`: it extracts the bearer token, validates the signature via the IdP's JWKS (or introspects opaque tokens), checks `iss`, `exp` and your audience, converts claims into authorities, and applies URL/method rules. Disable sessions and CSRF, map roles explicitly, and still enforce object-level ownership.

### Must-Know Bullets
- `issuer-uri` or `jwk-set-uri` configures the decoder.
- Default authorities are `SCOPE_*`.
- Validate the audience yourself.
- 401 = invalid token; 403 = insufficient scope.
- Introspection for revocability, JWT for speed.

### Common Follow-Up Questions
1. How do you map Keycloak realm roles?
2. JWT vs opaque in a resource server?
3. Why does my POST return 403 with a valid token?
4. How do you support two identity providers?
5. How do you validate the audience?

### 🚩 Red Flags
- Accepting any token from the issuer for any API.
- Rolling your own JWT filter instead of the starter.
- Disabling signature validation "for tests" in config shared with prod.
