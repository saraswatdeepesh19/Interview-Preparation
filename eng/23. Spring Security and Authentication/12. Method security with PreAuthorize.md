# Method security with PreAuthorize

---

## 🟢 Junior Level

### 1. Definition

**Method security** puts access rules directly on Java methods using annotations, so that business code is protected regardless of which controller, scheduler or message listener calls it. `@PreAuthorize` checks a rule **before** the method runs; if the rule fails, the method is never executed and an `AccessDeniedException` is thrown.

### 2. Analogy

URL rules are the guard at the building entrance; method security is the lock on each office door inside.

### 3. Enabling and Using

```java
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;

@Configuration
@EnableMethodSecurity          // Spring Security 6: prePostEnabled = true by default
public class MethodSecurityConfig { }
```

```java
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.stereotype.Service;

@Service
public class ReportService {

    @PreAuthorize("hasRole('ADMIN')")
    public void deleteAllReports() { /* ... */ }

    @PreAuthorize("hasAuthority('report:read')")
    public String readReport(long id) { return "report " + id; }

    @PreAuthorize("isAuthenticated()")
    public String myReports() { return "mine"; }
}
```

`@EnableMethodSecurity` replaces the deprecated `@EnableGlobalMethodSecurity`.

## 🟡 Middle Level

### 1. The Annotations

| Annotation | When evaluated | Typical use |
| :--- | :--- | :--- |
| `@PreAuthorize` | Before invocation | Role/permission/ownership by arguments |
| `@PostAuthorize` | After; can inspect `returnObject` | Check ownership of the *loaded* entity |
| `@PreFilter` | Filters a collection argument | Remove items the user can't touch |
| `@PostFilter` | Filters returned collection | Per-element visibility (inefficient at scale) |
| `@Secured`, `@RolesAllowed` | Simple role lists | Legacy / JSR-250 (`jsr250Enabled`) |

### 2. SpEL Expressions

```java
@PreAuthorize("hasAnyRole('ADMIN','MANAGER')")
@PreAuthorize("hasAuthority('SCOPE_orders.write') and #order.customerId == authentication.name")
@PreAuthorize("#username == authentication.principal.username")
@PostAuthorize("returnObject.owner == authentication.name or hasRole('ADMIN')")
@PreAuthorize("@orderPolicy.canView(authentication, #id)")     // delegate to a bean
```

Parameter names in `#id` need `-parameters` compilation (Boot's Gradle/Maven plugins enable it) or `@P("id")`.

### 3. Policy Bean for Complex Rules

```java
@Component("orderPolicy")
public class OrderPolicy {
    private final OrderRepository repo;
    public OrderPolicy(OrderRepository repo) { this.repo = repo; }

    public boolean canView(Authentication auth, long orderId) {
        return repo.findOwnerById(orderId)
                   .map(owner -> owner.equals(auth.getName()) || hasRole(auth, "ADMIN"))
                   .orElse(false);
    }
    private boolean hasRole(Authentication a, String r) {
        return a.getAuthorities().stream().anyMatch(g -> g.getAuthority().equals("ROLE_" + r));
    }
}

@Service
class OrderService {
    @PreAuthorize("@orderPolicy.canView(authentication, #id)")
    public Order get(long id) { /* ... */ return null; }
}
```

### 4. Custom Meta-Annotation

```java
import java.lang.annotation.*;

@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@PreAuthorize("hasRole('ADMIN')")
public @interface IsAdmin { }
```

Spring Security 6 supports meta-annotations and also **templates** (`@AuthorizeReturnObject`, `${...}` placeholders in 6.3).

### 5. Common Mistakes

- **Self-invocation:** calling `this.protectedMethod()` bypasses the proxy, so no check happens. Move to another bean.
- **`@PreAuthorize` on `private`/`final`/`static` methods** - silently ignored by proxies.
- Annotating a controller only and forgetting service methods invoked by jobs.
- `@PostFilter` on huge collections - loads everything then filters (O(n) and leaks via timing). Filter in the query instead.
- Mixing `hasRole('ROLE_ADMIN')` (double-prefix confusion); `hasRole('ADMIN')` already adds `ROLE_`.
- Exception handling: `AccessDeniedException` thrown inside the service is translated to 403 by `ExceptionTranslationFilter` only inside web requests; in async/message code you must handle it.

## 🔴 Senior Level

### 1. How It Works Internally

In Spring Security 6, `@EnableMethodSecurity` registers advisors (`AuthorizationManagerBeforeMethodInterceptor`, `AuthorizationManagerAfterMethodInterceptor`) in the AOP infrastructure. For `@PreAuthorize`, a `PreAuthorizeAuthorizationManager` parses the SpEL with a `MethodSecurityExpressionHandler` (`DefaultMethodSecurityExpressionHandler`), builds a `MethodSecurityExpressionRoot` (providing `hasRole`, `authentication`, `principal`), and returns an `AuthorizationDecision`. Proxy creation: CGLIB for classes, JDK proxies for interfaces. This replaces the old `AccessDecisionManager`/voter model - **voters are gone**.

Ordering: security advisors run with order `AuthorizationInterceptorsOrder` - *before* `@Transactional` by default (`PRE_AUTHORIZE` < transaction) so denied calls don't open a transaction. For `@PostAuthorize` the transaction is already open; heavy loads before denial are wasted.

### 2. Custom Expression Root / Permission Evaluator

```java
@Bean
static MethodSecurityExpressionHandler expressionHandler(PermissionEvaluator evaluator) {
    DefaultMethodSecurityExpressionHandler h = new DefaultMethodSecurityExpressionHandler();
    h.setPermissionEvaluator(evaluator);
    return h;
}

@Component
class DocPermissionEvaluator implements PermissionEvaluator {
    @Override public boolean hasPermission(Authentication a, Object target, Object permission) {
        return target instanceof Document d && d.getOwner().equals(a.getName());
    }
    @Override public boolean hasPermission(Authentication a, java.io.Serializable id, String type, Object permission) {
        return false;      // look up by id/type
    }
}
// @PreAuthorize("hasPermission(#doc, 'WRITE')")
```

Declare the handler bean `static` so it doesn't force early initialisation of the config class.

### 3. Performance

Each call parses SpEL (cached after first use) and evaluates reflectively: ~1-5 microseconds for simple expressions - negligible. The cost is *what the expression calls*: a policy bean doing a DB lookup on every invocation. Mitigate by (a) reusing the entity you load anyway via `@PostAuthorize`, (b) passing the needed attributes from the token, (c) caching ownership decisions per request.

### 4. Domain-Level Enforcement

Complement annotations with query-level constraints to prevent leaks: Spring Data `@Query("... where o.owner = ?#{authentication.name}")` via `SecurityEvaluationContextExtension`, or Hibernate filters for tenants. `@PostFilter` for a 100k-row list is a performance and data-exposure trap.

### 5. Observability and Testing

Listen for `AuthorizationDeniedEvent` (published through an `AuthorizationEventPublisher`) to log denials:

```java
@Bean
AuthorizationEventPublisher publisher(ApplicationEventPublisher p) {
    return new SpringAuthorizationEventPublisher(p);
}
@EventListener
void denied(AuthorizationDeniedEvent<?> e) {
    log.warn("denied user={} decision={}", e.getAuthentication().get().getName(), e.getAuthorizationDecision());
}
```

Test with `@WithMockUser(roles = "ADMIN")` on `@SpringBootTest` slices that include the proxy ([Testing secured endpoints](22.%20Testing%20secured%20endpoints.md)).

### 6. Pitfall: Reactive & Async

Method security with `@Async` or reactive return types requires the context to be present at **proxy invocation time**; for reactive use `@EnableReactiveMethodSecurity`.

## 🎯 Interview Cheat Sheet

### 30-Second Elevator Pitch
`@EnableMethodSecurity` + `@PreAuthorize` lets you declare authorization rules in SpEL on service methods: roles, authorities, argument-based ownership checks, or delegation to a policy bean. It works through AOP proxies and `AuthorizationManager`s, so remember proxy caveats (self-invocation, private methods). Combine with URL rules and query-level filtering for defence in depth.

### Must-Know Bullets
- `@EnableMethodSecurity` replaces `@EnableGlobalMethodSecurity`.
- `hasRole('X')` adds `ROLE_`; `hasAuthority` doesn't.
- `@PostAuthorize` sees `returnObject`.
- Self-invocation bypasses checks.
- Prefer policy beans over long SpEL.

### Common Follow-Up Questions
1. Why did my `@PreAuthorize` not trigger?
2. `@PreAuthorize` vs `@Secured` vs `@RolesAllowed`?
3. How do you check that the user owns the entity?
4. Why avoid `@PostFilter` on big collections?
5. What replaced `AccessDecisionVoter`?

### 🚩 Red Flags
- Security rules only on controllers.
- Business logic in SpEL strings.
- Relying on method security on private methods.
