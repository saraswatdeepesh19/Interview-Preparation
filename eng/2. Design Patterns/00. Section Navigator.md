## 🔗 Key Topic Relationships

### Singleton Topic Cluster
```
Q3 (Singleton) ──> Q4 (Thread-safe) ──> Q5 (DCL) ──> Q6 (Problems)
```
- **Q4 ↔ Q5:** Double-Checked Locking is an optimization of synchronized lazy initialization.
- **Q6 ↔ Q3:** Spring ApplicationContext and DI containers eliminate mutable static Singleton anti-patterns.

### Creational Patterns Cluster
```
Q7 (Factory Method vs Abstract) ──> Q8 (Builder) ──> Q9 (Prototype)
```
- **Q7 ↔ Q8:** Factory manages polymorphic object creation; Builder manages complex multi-attribute parameter assembly.
- **Q8 ↔ Q9:** Builder constructs new instances step-by-step; Prototype clones existing pre-configured instances.

### Behavioral Patterns Cluster
```
Q10 (Strategy) ──> Q11 (Observer) ──> Q13 (State vs Strategy)
```
- **Q10 ↔ Q13:** Strategy swaps independent interchangeable algorithms externally; State changes behavior based on internal state transitions.
- **Q11 ↔ Q13:** Observer decouples publishers from listeners; State decouples context from complex branching logic.

### Structural Patterns Cluster
```
Q12 (Decorator) ──> Q14 (Proxy) ──> Q15 (Iterator)
```
- **Q12 ↔ Q14:** Decorator adds new functional responsibilities; Proxy controls or intercepts access without altering interface semantics.

## 🎓 Level-by-Level Knowledge Matrix

### 🟢 Junior
- Patterns are reusable, standardized solutions to recurring software engineering problems.
- 3 primary GoF categories: **Creational**, **Structural**, **Behavioral**.
- Singleton provides a single JVM instance; Factory abstracts object instantiation; Builder avoids telescoping constructors.

### 🟡 Middle
- Bill Pugh Singleton idiom leverages JVM classloader initialization guarantees without explicit locks.
- DCL requires `volatile` to prevent instruction reordering on out-of-order CPU execution.
- Prefer composition over inheritance to prevent class explosion ($N$ decorators vs $2^N$ subclasses).
- Strategy implementations are simplified via Java 8+ lambdas and functional interfaces (`Function`, `Consumer`, `Predicate`).

### 🔴 Senior
- Java Memory Model (JMM): `volatile` provides *happens-before* consistency and memory barriers.
- JIT Monomorphic vs Megamorphic call sites: excessive strategy polymorphism (>2 implementations) disables vtable inline caching.
- CGLIB / ByteBuddy vs JDK Dynamic Proxy: interface vs subclass generation, reflection costs, and AOP self-invocation traps.
- Sealed classes (Java 17+) provide exhaustive pattern matching for clean state machine dispatching.
