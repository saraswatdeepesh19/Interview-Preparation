# What are Java UI alternatives Thymeleaf Vaadin and HTMX

---

## 🟢 Junior Level

Not every web UI needs a separate React/Angular SPA. Java teams have server-centric alternatives that keep most logic in Java:

| Approach | How it works | Best for |
| --- | --- | --- |
| **Thymeleaf** (server-side templates) | Spring MVC controllers render HTML templates on the server; full page loads | Admin panels, back-office tools, content pages, forms |
| **HTMX + Thymeleaf** | HTML attributes trigger AJAX requests that return **HTML fragments** swapped into the page | Interactive apps without a JS framework |
| **Vaadin Flow** | Write the UI entirely in Java components; Vaadin syncs state between server and browser | Data-heavy business apps, internal tools, Java-only teams |
| **Vaadin Hilla / SPA + REST** | TypeScript/React frontend with type-safe calls to Java endpoints | When you want a modern SPA with Java backend type safety |
| **JSF / Jakarta Faces** | Component framework (legacy enterprise) | Maintaining existing systems |

### Thymeleaf example

```java
@Controller
class OrderPageController {
    @GetMapping("/orders")
    String list(Model model, @RequestParam(defaultValue = "ALL") String status) {
        model.addAttribute("orders", orders.find(status));
        model.addAttribute("status", status);
        return "orders/list";                     // templates/orders/list.html
    }
}
```

```html
<table>
  <tr th:each="o : ${orders}">
    <td th:text="${o.id}">42</td>                 <!-- th:text escapes HTML (XSS-safe) -->
    <td th:text="${o.status}">PAID</td>
    <td th:text="${#numbers.formatDecimal(o.total, 1, 2)}">49.90</td>
  </tr>
</table>
```

## 🟡 Middle Level

### HTMX: hypermedia-driven interactivity
HTMX extends HTML with attributes like `hx-get`, `hx-post`, `hx-target`, `hx-swap`, `hx-trigger`. The server returns HTML, not JSON.

```html
<!-- Live search: request a fragment as the user types -->
<input type="search" name="q"
       hx-get="/orders/search" hx-trigger="input changed delay:300ms"
       hx-target="#results" hx-swap="innerHTML">
<div id="results"></div>

<!-- Inline action without page reload -->
<button hx-post="/orders/42/cancellation" hx-target="closest tr" hx-swap="outerHTML"
        hx-confirm="Cancel this order?">Cancel</button>
```

```java
@GetMapping("/orders/search")
String search(@RequestParam String q, Model model) {
    model.addAttribute("orders", orders.search(q));
    return "orders/list :: rows";                 // Thymeleaf fragment
}
```

Benefits: one codebase, no JSON API layer or client-side state for many interactions, server-side authorization and validation stay authoritative, small JS footprint (~14 KB). Libraries like `htmx-spring-boot` add helpers (detect `HX-Request` headers, out-of-band swaps).

### Vaadin Flow

```java
@Route("orders")
public class OrdersView extends VerticalLayout {
    public OrdersView(OrderService service) {
        Grid<Order> grid = new Grid<>(Order.class, false);
        grid.addColumn(Order::id).setHeader("ID");
        grid.addColumn(Order::status).setHeader("Status");
        grid.setItems(query -> service.page(query.getOffset(), query.getLimit()).stream());   // lazy loading

        Button refresh = new Button("Refresh", e -> grid.getDataProvider().refreshAll());
        add(refresh, grid);
    }
}
```

The UI state lives on the server (per user session); the browser renders web components and sends events over a websocket/XHR channel.

## 🔴 Senior Level

### Trade-offs

| Concern | Thymeleaf/HTMX | Vaadin Flow | SPA (React/Angular) + REST |
| --- | --- | --- | --- |
| Team skills | Java + HTML/CSS | Java only | Separate frontend expertise |
| Interactivity | Good for CRUD/forms; complex client-side UX gets hard | Rich components (grids, forms) | Unlimited |
| Server load / scale | Stateless rendering, cache-friendly | **Stateful sessions** — memory per user, sticky sessions | Stateless API; client does rendering |
| Offline / mobile apps | No | No | Yes (PWA), shared API for mobile |
| SEO / first load | Excellent | Moderate | Needs SSR for SEO |
| API reuse by other clients | Need a separate API anyway | Need a separate API | API is the product |

### Choosing pragmatically
* **Internal tools, admin back-offices, line-of-business apps** with a Java team: Thymeleaf + HTMX or Vaadin deliver fast with fewer moving parts (one deployable, one language, no API versioning between UI and backend).
* **Customer-facing products** with complex UX, mobile apps, or separate frontend teams: SPA/SSR frameworks with a well-designed API.
* **Mixed**: server-rendered pages with islands of interactivity (HTMX, Alpine.js, or a few React components) — avoids the "SPA by default" cost.

### Production considerations
* Thymeleaf: enable template caching in production (`spring.thymeleaf.cache=true`, default), use fragments for reuse, CSRF tokens are inserted automatically into forms (`th:action`), and keep `th:utext` away from user content.
* HTMX: handle errors (`htmx:responseError` events), return proper status codes, use `HX-Redirect`/`HX-Trigger` response headers for navigation and events, and protect state-changing requests with CSRF tokens (send them via `hx-headers` or meta tag configuration).
* Vaadin: size memory for sessions (UI component trees per user), configure session timeouts, use sticky sessions behind load balancers (or Vaadin's clustering/serialization support), and load test with realistic concurrent users.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Java teams can build web UIs without a separate SPA: Thymeleaf renders HTML server-side, HTMX adds interactivity by swapping server-rendered HTML fragments in response to attributes like `hx-get`, and Vaadin Flow lets you write the whole UI in Java with server-side state. They're great for internal and business apps with Java teams; SPAs remain better for complex customer-facing UX, mobile and offline needs, and when the API is the product.

**Must know:**
* Thymeleaf basics, fragments, `th:text` vs `th:utext`.
* HTMX attributes and the hypermedia approach; fragment endpoints.
* Vaadin Flow server-side state model and its scaling implications.
* Trade-off table vs SPA.
* CSRF, caching and session considerations in production.

**Common follow-ups:**
* Would you build our admin panel with React or HTMX?
* How does Vaadin scale with 10,000 concurrent users?
* How do you handle validation errors with HTMX?

**Red flags:** choosing an SPA framework by default for a simple CRUD back-office; Vaadin without session sizing.
