# How does prototypal inheritance work in JavaScript

---

## 🟢 Junior Level

In JavaScript, every object has a hidden link to another object called its **prototype**. When you read a property that the object does not have, the engine follows that link and looks on the prototype, then on the prototype's prototype, and so on until it reaches `null`. This lookup path is the **prototype chain**. It is how JavaScript objects "inherit" behavior.

### Simple Real-World Analogy
Imagine asking an employee a question. If they do not know the answer they ask their manager, who asks *their* manager, up to the CEO. If nobody knows, the answer is "undefined". The reporting line is the prototype chain.

```mermaid
graph LR
    A["dog = {name: 'Rex'}"] --> B["Dog.prototype {bark()}"]
    B --> C["Animal.prototype {eat()}"]
    C --> D["Object.prototype {toString()}"]
    D --> E["null"]
```

### Minimal example

```js
const animal = {
  eat() { return `${this.name} eats`; }
};

const dog = Object.create(animal);   // dog.__proto__ === animal
dog.name = 'Rex';

console.log(dog.eat());                       // Rex eats  (found on animal)
console.log(Object.getPrototypeOf(dog) === animal); // true
console.log(dog.hasOwnProperty('eat'));        // false
```

### Java developer warning
Unlike Java, JavaScript has no class-based inheritance at runtime. The `class` keyword (ES2015) is **syntactic sugar** over prototypes. Objects inherit directly from other *objects*, not from blueprints.

### Same thing with `class`

```js
class Animal {
  constructor(name) { this.name = name; }
  eat() { return `${this.name} eats`; }
}
class Dog extends Animal {
  bark() { return `${this.name} barks`; }
}
const d = new Dog('Rex');
console.log(d.eat(), d.bark());
console.log(d instanceof Animal); // true
```

## 🟡 Middle Level

### `__proto__`, `prototype` and `[[Prototype]]`
| Term | Meaning |
|---|---|
| `[[Prototype]]` | the internal link of every object |
| `obj.__proto__` | legacy accessor to `[[Prototype]]` (use `Object.getPrototypeOf`) |
| `Fn.prototype` | an ordinary property on *functions*: the object that becomes `[[Prototype]]` of instances created with `new Fn()` |

```js
function Person(name) { this.name = name; }
Person.prototype.hi = function () { return 'Hi ' + this.name; };

const p = new Person('Ann');
p.__proto__ === Person.prototype;            // true
Person.prototype.constructor === Person;      // true
```

### What `new` does (four steps)
1. Create an empty object.
2. Set its `[[Prototype]]` to `Fn.prototype`.
3. Call `Fn` with `this` bound to that object.
4. Return the object (unless the function returns another object).

```js
function myNew(Fn, ...args) {
  const obj = Object.create(Fn.prototype);
  const result = Fn.apply(obj, args);
  return result instanceof Object ? result : obj;
}
```

### Property reads vs writes
Reads walk the chain; **writes create an own property** on the receiver (shadowing the inherited one), unless the inherited one is a setter or non-writable.

```js
const base = { count: 0 };
const child = Object.create(base);
child.count++;                 // creates child.count = 1 ; base.count remains 0
console.log(base.count, child.count); // 0 1
```

Danger: mutable objects on the prototype are shared by all instances.

```js
function Cart() {}
Cart.prototype.items = [];            // shared across ALL carts: bug
new Cart().items.push('a');
console.log(new Cart().items);        // ['a']
```

### Prototype vs instance methods in classes

```js
class Counter {
  count = 0;                  // own property per instance
  inc() { this.count++; }     // on Counter.prototype (shared)
  dec = () => { this.count--; } // own property per instance (bound this, more memory)
}
```

### Useful APIs
- `Object.create(proto, descriptors)`, `Object.getPrototypeOf`, `Object.setPrototypeOf` (slow: avoid).
- `Object.hasOwn(obj, key)` (ES2022) replaces `hasOwnProperty`.
- `instanceof` checks if `Fn.prototype` is anywhere on the chain.
- `Object.create(null)` produces a dictionary object with no prototype (safe map).
- `for...in` enumerates inherited enumerable properties; prefer `Object.keys/entries`.

### Common mistakes
- Assigning methods inside the constructor (each instance gets its own copy).
- Modifying built-in prototypes (`Array.prototype.last = ...`) — breaks libraries, "monkey patching".
- Forgetting `super(...)` before using `this` in derived constructors.
- Confusing `prototype` with `__proto__`.

## 🔴 Senior Level

### Engine optimizations: hidden classes and inline caches
V8 assigns objects with the same shape (property order) a **hidden class**. Property access sites cache the shape → fast offset lookup. Changing the prototype with `Object.setPrototypeOf`, deleting properties (`delete obj.x`) or adding properties in different orders produces shape transitions/dictionary mode and de-optimizes hot paths.

```js
// Monomorphic: consistent shape
const make = (x, y) => ({ x, y });
// Polymorphic/megamorphic: different key orders or extra optional fields in hot loops hurt
```

### Prototype pollution: a real security vulnerability
If a merge/set utility copies attacker-controlled keys like `__proto__`, `constructor` or `prototype`, it can modify `Object.prototype` for the *entire process*, leading to privilege bypass or RCE in Node servers.

```js
// Vulnerable deep merge
function merge(target, src) {
  for (const key in src) {
    if (typeof src[key] === 'object') merge(target[key] ??= {}, src[key]);
    else target[key] = src[key];
  }
}
merge({}, JSON.parse('{"__proto__": {"isAdmin": true}}'));
console.log({}.isAdmin); // true  - every object is now "admin"
```

Mitigations: reject `__proto__`/`constructor`/`prototype` keys, use `Map`, create dictionaries with `Object.create(null)`, `Object.freeze(Object.prototype)` in hardened environments, Node `--disable-proto=delete`, keep libraries patched (lodash, minimist CVEs).

### Mixins and composition

```js
const Serializable = Base => class extends Base {
  toJSONString() { return JSON.stringify(this); }
};
const Timestamped = Base => class extends Base {
  createdAt = Date.now();
};
class Order extends Timestamped(Serializable(Object)) {}
```

JavaScript supports single inheritance chains only; composition via mixins, functions or delegation avoids deep hierarchies. Modern guidance matches the Java mantra: favor composition over inheritance.

### Inheriting from built-ins and Symbol-based protocols
Subclassing `Array`, `Error` or `Map` works in ES2015+ (needs native class support, not transpiled to ES5). Custom errors:

```js
class HttpError extends Error {
  constructor(status, message, options) {
    super(message, options);          // options.cause (ES2022)
    this.name = 'HttpError';
    this.status = status;
  }
}
try { throw new HttpError(404, 'Not found', { cause: new Error('db miss') }); }
catch (e) { console.log(e instanceof HttpError, e.cause.message); }
```

`Symbol.hasInstance`, `Symbol.iterator`, `Symbol.toPrimitive` customize behavior through well-known symbols on the prototype.

### TypeScript note
TypeScript `class` compiles to the same prototype mechanism; types are erased. TS `private` is compile-time only, whereas `#private` is runtime-enforced. Structural typing means two unrelated classes with the same shape are compatible — unlike Java's nominal typing.

## 🎯 Interview Cheat Sheet

**30-second pitch:** JS objects link to a prototype; property lookup walks that chain until `null`. `class` is sugar over it. `new` creates an object linked to `Fn.prototype`. Share methods on prototypes, avoid shared mutable prototype state, never trust user-controlled keys (prototype pollution), and prefer composition.

**Must-know bullets**
- `Object.getPrototypeOf(x) === Fn.prototype` for instances.
- Reads climb the chain; writes shadow.
- `instanceof`, `hasOwn`, `Object.create`.
- `class` = syntactic sugar; `#private` is truly private.
- Prototype pollution and its mitigations.

**Common follow-up questions**
1. Difference between `__proto__` and `prototype`?
2. What does `new` do internally?
3. How would you implement `instanceof`?
4. How is JS inheritance different from Java's?

**Red flags**
- "JavaScript classes work exactly like Java classes."
- Mutating `Object.prototype` or built-ins.
- Merging untrusted JSON into objects with a naive recursive merge.
