# What are React hooks and reconciliation

---

## 🟢 Junior Level

**React** builds UIs from **components** — functions that take **props** and return a description of the UI (JSX). When data changes, React re-runs the component and updates the browser DOM efficiently.

**Hooks** are functions (named `useSomething`) that let function components hold state and run side effects:

```tsx
import { useState, useEffect } from 'react';

function OrderBadge({ orderId }: { orderId: string }) {
  const [order, setOrder] = useState<Order | null>(null);     // state that survives re-renders
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {                                            // side effect after render
    const controller = new AbortController();
    fetch(`/api/orders/${orderId}`, { signal: controller.signal })
      .then(r => (r.ok ? r.json() : Promise.reject(new Error(`HTTP ${r.status}`))))
      .then(setOrder)
      .catch(e => { if (e.name !== 'AbortError') setError(e.message); });
    return () => controller.abort();                           // cleanup when orderId changes or unmount
  }, [orderId]);                                               // re-run only when orderId changes

  if (error) return <span className="badge error">{error}</span>;
  if (!order) return <span className="badge">Loading…</span>;
  return <span className="badge">{order.status}</span>;
}
```

### Rules of hooks
1. Call hooks only at the **top level** of a component or custom hook — not inside loops, conditions or nested functions.
2. Call hooks only from React function components or custom hooks.

React identifies each hook's state by **call order**, so the order must be identical on every render.

## 🟡 Middle Level

### Core hooks

| Hook | Purpose |
| --- | --- |
| `useState` | Local state; setter triggers a re-render |
| `useReducer` | State transitions via a reducer (complex state) |
| `useEffect` | Synchronize with external systems (fetch, subscriptions, timers) after render |
| `useLayoutEffect` | Like effect but runs before paint (measure layout) |
| `useMemo` | Memoize an expensive computed value |
| `useCallback` | Memoize a function identity (for memoized children / effect deps) |
| `useRef` | Mutable value that doesn't trigger re-renders; DOM refs |
| `useContext` | Read context (theme, auth, i18n) without prop drilling |

### Reconciliation: how React updates the DOM
1. A state change schedules a re-render of that component (and its children).
2. React builds a new **element tree** and **diffs** it against the previous one (the "virtual DOM" comparison).
3. Heuristics make diffing O(n): elements of **different types** are replaced entirely; same type → update props and recurse; lists are matched by **`key`**.
4. Only the minimal DOM changes are applied (commit phase).

```tsx
// Keys must be stable and unique among siblings — NOT the array index if items can reorder
<ul>
  {orders.map(o => <OrderRow key={o.id} order={o} />)}
</ul>
```

Using the index as a key with reorderable/insertable lists makes React reuse the wrong components — state (input values, checkboxes) "jumps" between rows.

### Custom hooks: reuse stateful logic

```tsx
function useDebouncedValue<T>(value: T, delayMs = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(t);
  }, [value, delayMs]);
  return debounced;
}
```

## 🔴 Senior Level

### Effects are for synchronization, not data flow
Common mistakes:
* **Derived state in effects** — computing `fullName` in `useEffect` + `setState` causes an extra render; compute it during render (or `useMemo` if expensive).
* **Missing dependencies** → stale closures (an interval reading an old `count`). Use the ESLint `react-hooks/exhaustive-deps` rule; use functional updates (`setCount(c => c + 1)`).
* **Race conditions** in fetching effects — responses arriving out of order overwrite newer data; abort previous requests (as above) or ignore stale results.
* In development, React 18 **StrictMode** mounts, unmounts and re-mounts components to surface missing cleanups — effects run twice there by design.

For server data, prefer a data-fetching library (**TanStack Query**, SWR, or framework loaders) that handles caching, deduplication, retries, background refresh and race conditions, instead of hand-written effects.

### Rendering performance
* A parent re-render re-renders all children by default. Use `React.memo` for expensive pure children, with stable props (`useCallback`/`useMemo`) — but measure with the React Profiler first; memoization has costs.
* Keep state as **local** as possible; lifting state to the top makes the whole tree re-render.
* Split contexts by update frequency (a frequently changing value in a large context re-renders all consumers).
* Virtualize long lists (react-window/TanStack Virtual).
* The **React Compiler** (React 19 era) can auto-memoize components and hooks, reducing manual `useMemo`/`useCallback`.

### Concurrent rendering (React 18+)
* Rendering is **interruptible**: `useTransition` marks updates as non-urgent (filtering a big list) so typing stays responsive; `useDeferredValue` renders a lagging version of a value.
* **Automatic batching** groups multiple state updates into one render, including in promises and timeouts.
* **Suspense** lets components "wait" for data/code with fallbacks; with server components and streaming SSR (Next.js App Router), parts of the page render on the server and stream to the client.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Hooks give function components state (`useState`, `useReducer`), side effects (`useEffect`), memoization (`useMemo`, `useCallback`), refs and context, and must be called unconditionally at the top level because React tracks them by call order. On every state change React re-renders, diffs the new element tree against the old one — replacing different types and matching list items by stable keys — and applies minimal DOM updates. Effects are for synchronizing with external systems, with cleanup and correct dependencies.

**Must know:**
* Rules of hooks and why.
* Core hooks table; custom hooks.
* Reconciliation heuristics; stable keys.
* Effect pitfalls: derived state, stale closures, races, StrictMode double run.
* Performance: local state, `React.memo`, context splitting, virtualization; transitions.

**Common follow-ups:**
* Why shouldn't you use the array index as a key?
* Why does my effect run twice?
* When would you use `useMemo`?

**Red flags:** fetching in effects without cleanup/race handling; hooks in conditions; memoizing everything blindly.
