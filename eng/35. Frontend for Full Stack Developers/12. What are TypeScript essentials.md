# What are TypeScript essentials

---

## 🟢 Junior Level

**TypeScript** is JavaScript with a **static type system**. The compiler (`tsc`) checks types and then emits plain JavaScript — types disappear at runtime (**type erasure**, like Java generics). It catches whole classes of bugs before code runs and makes large frontends maintainable, which is why most React/Angular/Vue codebases use it.

```typescript
// Primitive and object types
let count: number = 0;
const title: string = 'Orders';

interface Order {
  id: string;
  status: 'PENDING' | 'PAID' | 'SHIPPED';    // union of literal types
  total: number;
  note?: string;                               // optional property
  readonly createdAt: string;
}

function formatTotal(order: Order): string {
  return `${order.total.toFixed(2)} EUR`;
}

// Type inference: no annotation needed
const orders = [{ id: '1', status: 'PAID', total: 10, createdAt: '2026-10-16' }] satisfies Order[];
```

### Mental model for Java developers
* TypeScript is **structurally typed**: an object is compatible with an interface if it has the required shape — no `implements` needed (Java is nominal).
* Types are compile-time only: no runtime type checks unless you write them.
* `any` turns the checker off; `unknown` is the type-safe "could be anything" — you must narrow it before use.

## 🟡 Middle Level

### Unions, narrowing and discriminated unions

```typescript
type ApiResult<T> =
  | { kind: 'ok'; data: T }
  | { kind: 'error'; status: number; message: string };

function render(result: ApiResult<Order>) {
  switch (result.kind) {                // discriminant narrows the type in each branch
    case 'ok':    return `Order ${result.data.id}`;
    case 'error': return `Failed (${result.status}): ${result.message}`;
    default: {
      const exhaustive: never = result;  // compile error if a new kind is added and not handled
      return exhaustive;
    }
  }
}
```

This is the TypeScript equivalent of Java sealed interfaces + pattern matching.

### Generics and utility types

```typescript
function first<T>(items: T[]): T | undefined { return items[0]; }

type OrderPatch   = Partial<Order>;                  // all properties optional
type OrderSummary = Pick<Order, 'id' | 'status'>;    // subset of properties
type NewOrder     = Omit<Order, 'id' | 'createdAt'>; // remove properties
type ById         = Record<string, Order>;           // map type
type Status       = Order['status'];                 // indexed access type
```

### `tsconfig` settings that matter

```json
{
  "compilerOptions": {
    "strict": true,                       // enables strictNullChecks, noImplicitAny, etc.
    "noUncheckedIndexedAccess": true,     // arr[i] is T | undefined
    "exactOptionalPropertyTypes": true,
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler"
  }
}
```

With `strictNullChecks`, `null` and `undefined` must be handled explicitly — the biggest single source of prevented bugs.

## 🔴 Senior Level

### Types at the network boundary
TypeScript types don't validate JSON from the server: `await res.json() as Order` is an unchecked cast. Options:
* **Generate types from the API contract** — OpenAPI → TypeScript (`openapi-typescript`, `orval`), GraphQL → TypeScript (GraphQL Code Generator). Backend changes break the frontend build instead of production.
* **Runtime validation** with schemas (Zod, Valibot) where data is untrusted or contracts are loose:

```typescript
import { z } from 'zod';

const OrderSchema = z.object({
  id: z.string(),
  status: z.enum(['PENDING', 'PAID', 'SHIPPED']),
  total: z.number(),
  createdAt: z.string().datetime(),
});
type Order = z.infer<typeof OrderSchema>;           // one source of truth for type and validation

const order = OrderSchema.parse(await res.json());  // throws with a precise error if the shape is wrong
```

### Advanced type features worth recognizing
* **Conditional types** and `infer`: `type Awaited<T> = T extends Promise<infer U> ? U : T`.
* **Mapped types**: `type ReadonlyDeep<T> = { readonly [K in keyof T]: ReadonlyDeep<T[K]> }`.
* **Template literal types**: `` type Route = `/api/${'orders' | 'customers'}/${string}` ``.
* **Branded types** for IDs to prevent mixing them up (nominal typing simulation):

```typescript
type OrderId = string & { readonly __brand: 'OrderId' };
type CustomerId = string & { readonly __brand: 'CustomerId' };
function loadOrder(id: OrderId) { /* ... */ }
// loadOrder(customerId)  -> compile error
```

* **`satisfies`** (TS 4.9+) checks an expression against a type without widening its inferred type.

### Pragmatics in large codebases
* Ban `any` via lint rules (`@typescript-eslint/no-explicit-any`), allow `unknown` + narrowing.
* Prefer `type`/`interface` for shapes and avoid TypeScript `enum` in favor of union literals or `as const` objects (enums emit runtime code and have quirks).
* Type-check in CI (`tsc --noEmit`) separately from bundling — many bundlers (esbuild, SWC, Vite) strip types without checking them.
* Large numeric IDs (> 2^53) must be strings — JavaScript `number` is a double.

## 🎯 Interview Cheat Sheet

**30-second pitch:** TypeScript adds a structural, compile-time type system to JavaScript that's erased at runtime. Essentials are interfaces and type aliases, unions with narrowing and discriminated unions for exhaustive handling, generics and utility types like `Partial`, `Pick`, `Omit` and `Record`, and strict compiler settings. Because JSON from the network isn't checked, I generate types from OpenAPI or GraphQL contracts or validate at runtime with Zod, and type-check in CI with `tsc --noEmit`.

**Must know:**
* Structural vs nominal typing; erasure; `any` vs `unknown`.
* Unions, narrowing, discriminated unions with `never` exhaustiveness.
* Generics, utility types, indexed access types.
* `strict`, `strictNullChecks`, `noUncheckedIndexedAccess`.
* Boundary validation: generated types, Zod; branded IDs.

**Common follow-ups:**
* How do TypeScript generics differ from Java generics?
* Is `res.json() as Order` safe?
* `interface` vs `type`?

**Red flags:** `any` everywhere; `as` casts on API data without validation; disabling strict mode.
