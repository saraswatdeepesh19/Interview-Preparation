# What changed from Java 8 to 11 to 17 to 21

---

## 🟢 Junior Level

Java ships a feature release every six months; every two years one is a **Long-Term Support (LTS)** release. Most companies jump from LTS to LTS: **8 → 11 → 17 → 21** (and next 25).

| LTS | Year | Headline features |
| --- | --- | --- |
| **8** | 2014 | Lambdas, Streams, `Optional`, `java.time`, default methods |
| **11** | 2018 | `var` (10), `HttpClient`, `String` helpers, single-file launch `java Main.java`, ZGC (experimental) |
| **17** | 2021 | Records, sealed classes, text blocks, switch expressions, `instanceof` patterns, strong encapsulation of JDK internals |
| **21** | 2023 | Virtual threads, pattern matching for `switch`, record patterns, sequenced collections, generational ZGC |

### A taste of each

```java
// 8: lambdas + streams
List<String> names = users.stream().filter(User::active).map(User::name).toList(); // toList() is 16+

// 11: var + new String methods + HttpClient
var client = HttpClient.newHttpClient();
var body = client.send(HttpRequest.newBuilder(URI.create("https://example.org")).build(),
                       HttpResponse.BodyHandlers.ofString()).body();
boolean empty = "   ".isBlank();               // true
List<String> lines = "a\nb".lines().toList();

// 17: records, text blocks, switch expressions
record Money(BigDecimal amount, Currency currency) {}
String json = """
        {"status": "ok"}
        """;
int days = switch (month) { case FEBRUARY -> 28; case APRIL, JUNE, SEPTEMBER, NOVEMBER -> 30; default -> 31; };

// 21: virtual threads + pattern matching for switch
try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {
    ids.forEach(id -> exec.submit(() -> fetch(id)));
}
```

## 🟡 Middle Level

### Java 9–11 (beyond the language)
* **Module system** (9) — `module-info.java`, `jlink` to build trimmed runtimes.
* **Collection factories** (9) — `List.of`, `Set.of`, `Map.of` (immutable, null-hostile).
* `Optional.ifPresentOrElse`, `.or`, `.stream` (9), `.isEmpty` (11), `orElseThrow()` (10).
* **G1 becomes the default GC** (9); JDK 11 removes Java EE modules (JAXB, JAX-WS) and CORBA from the JDK — a classic migration break.
* **Flight Recorder open-sourced** (11).

### Java 12–17
* Switch expressions (14), text blocks (15), records (16), `instanceof` patterns (16), sealed classes (17).
* **Helpful NullPointerExceptions** (14): `Cannot invoke "String.length()" because "user.name" is null`.
* `Stream.toList()` (16), `Collectors.teeing` (12), `String.indent/transform` (12), `Files.mismatch` (12).
* **ZGC and Shenandoah production-ready** (15).
* **Strong encapsulation** (16/17): `--illegal-access` removed; reflective access to JDK internals now fails unless `--add-opens` is used.
* Removals: Nashorn JS engine (15), RMI activation, `SecurityManager` deprecated for removal (17).

### Java 18–21
* UTF-8 by default (18): `Charset.defaultCharset()` is UTF-8 everywhere — fixes and breaks Windows code that relied on cp1252.
* Simple web server `jwebserver` (18), code snippets in Javadoc (18).
* **Virtual threads** (21, JEP 444), **sequenced collections** (21: `getFirst()`, `getLast()`, `reversed()` on `List`, `Deque`, `LinkedHashMap`...), **generational ZGC** (21, `-XX:+ZGenerational`, default in 23).
* `String.indexOf(ch, from, to)`, `StringBuilder.repeat`, `Character.isEmoji` (21), `Math.clamp` (21).

## 🔴 Senior Level

### Runtime and performance changes that matter more than syntax
* **Container awareness** (backported to 8u191): JVM reads cgroup CPU and memory limits. Use `-XX:MaxRAMPercentage=75` instead of fixed `-Xmx` in Kubernetes; JDK 15+ supports cgroup v2.
* **G1 improvements** across releases: concurrent class unloading, abortable mixed collections, *uncommitting* idle heap back to the OS (12), and big pause-time wins. Many teams see 10–30% better throughput or lower p99 just from upgrading 8 → 17 with the same code.
* **Compact Strings** (9): Latin-1 strings use 1 byte per char — often 10–20% heap reduction in string-heavy apps.
* **CDS / AppCDS** (default CDS archive in 12, dynamic archiving in 13): faster startup; Spring Boot 3.3 supports CDS training runs.
* **Virtual threads** (21): blocking code (JDBC, `RestClient`) scales to tens of thousands of concurrent requests without reactive rewrites — but `synchronized` blocks around I/O *pinned* the carrier thread until JDK 24 (JEP 491); prefer `ReentrantLock` on 21.

### Ecosystem forcing functions
* **Spring Boot 3 / Spring Framework 6 require Java 17** and Jakarta EE 9+ (`javax.*` → `jakarta.*` package rename). This, not language features, is why most teams moved off 8/11.
* Hibernate 6, Jakarta Servlet 6, Jackson 2.15+ assume modern Java.
* Free public updates for Java 8 from Oracle ended long ago; vendor builds (Temurin, Corretto, Zulu) continue LTS updates for different durations — pick a vendor and track their support calendar.

### Release model and preview features
* Six-month cadence since Java 10; features go through **incubator** (`jdk.incubator.*`) and **preview** stages (`--enable-preview`) before becoming final. Never ship preview features to production — class files compiled with preview are tied to that exact JDK version.
* Interviewers like to ask the JEP path: virtual threads were preview in 19 and 20, final in 21; structured concurrency and scoped values continued as previews after 21.

### Migration risk map
| Upgrade | Typical breakage |
| --- | --- |
| 8 → 11 | Removed Java EE modules (JAXB, `javax.annotation`), `sun.misc` usage, Nashorn warnings, TLS 1.3 defaults |
| 11 → 17 | Strong encapsulation (`InaccessibleObjectException`), old Lombok/ByteBuddy/Mockito versions, removed GC flags (CMS removed in 14) |
| 17 → 21 | Old bytecode tools not understanding class file version 65, `Thread.stop`/`suspend` throw, finalization deprecation, dynamic agent loading warnings |

## 🎯 Interview Cheat Sheet

**30-second pitch:** Java 8 brought lambdas and streams; 11 added `var`, the HTTP client and removed Java EE modules; 17 delivered records, sealed types, text blocks and strong encapsulation; 21 added virtual threads, pattern matching for switch, record patterns and sequenced collections. The runtime also got much better — container awareness, G1/ZGC improvements, compact strings, CDS.

**Must know:**
* LTS releases: 8, 11, 17, 21 (next 25); six-month cadence.
* Spring Boot 3 requires Java 17 and the `jakarta.*` namespace.
* Strong encapsulation in 16/17 breaks reflective hacks.
* Virtual threads in 21; pinning with `synchronized` until JDK 24.
* Container-aware heap sizing with `MaxRAMPercentage`.

**Common follow-ups:**
* What would you upgrade first in a Java 8 codebase?
* What does "preview feature" mean?
* Which GC is default and when would you pick ZGC?

**Red flags:** knowing only syntax features; "we stay on 8 because it works"; enabling preview features in production.
