# What is reflection and when should you use it

---

## 🟢 Junior Level

**Reflection** (`java.lang.reflect`) lets code inspect and use classes, methods, fields and constructors **at run time**, even if their names were unknown at compile time.

```java
Class<?> type = Class.forName("com.shop.Order");

for (Field f : type.getDeclaredFields()) {
    System.out.println(f.getName() + " : " + f.getType().getSimpleName());
}

Object order = type.getDeclaredConstructor().newInstance();
Method setTotal = type.getMethod("setTotal", BigDecimal.class);
setTotal.invoke(order, new BigDecimal("99.90"));
```

### Who uses it
You rarely write reflection yourself, but frameworks depend on it:
* **Spring** — finding `@Component` classes, injecting constructors, reading annotations.
* **Jackson** — mapping JSON properties to fields/getters.
* **Hibernate** — reading and writing entity fields.
* **JUnit** — discovering and invoking `@Test` methods.

### Real-world analogy
Normally you call a colleague by name. Reflection is opening the company directory at run time, looking up "whoever handles invoices", and calling them — flexible, but slower and you only find out at run time if nobody has that role.

## 🟡 Middle Level

### Core API

```java
Class<Order> c = Order.class;

c.getDeclaredFields();      // all fields declared in Order, any visibility
c.getFields();              // public fields including inherited
c.getDeclaredMethods();     // all methods declared here
c.getMethod("total");       // public method incl. inherited
c.getRecordComponents();    // records (Java 16+)
c.getPermittedSubclasses(); // sealed types (Java 17+)

Field secret = c.getDeclaredField("internalNotes");
secret.setAccessible(true);                // bypass private (subject to module rules)
Object value = secret.get(order);

Transactional tx = c.getMethod("cancel").getAnnotation(Transactional.class);
```

### Generics at run time
Type erasure removes type arguments from *objects*, but declarations keep them in metadata:

```java
class OrderRepo implements Repository<Order, UUID> {}

ParameterizedType t = (ParameterizedType) OrderRepo.class.getGenericInterfaces()[0];
Type[] args = t.getActualTypeArguments();   // [class Order, class UUID]
```

This is how Spring resolves `Repository<Order, UUID>` and how Jackson's `TypeReference<List<Order>>` captures `List<Order>` via an anonymous subclass.

### When to use it yourself
* Building framework-like infrastructure: plugins, generic mappers, test utilities, annotation-driven configuration.
* Reading annotations for cross-cutting behavior.

### When not to
* Ordinary business logic — use interfaces, polymorphism, or a `Map` of handlers.
* Accessing private state of classes you don't own — it breaks on upgrades.
* Hot paths — see the cost below.

## 🔴 Senior Level

### Cost model
* **Lookup** (`getMethod`, `getDeclaredFields`) is expensive: it copies arrays and checks security; cache the results (`ClassValue<T>` is ideal: per-class lazy cache that doesn't leak class loaders).
* **Invocation**: since **JDK 18 (JEP 416)**, `Method.invoke` and `Field.get` are implemented on top of **method handles**, so after warm-up they can be JIT-inlined — much faster than the old "inflation" mechanism (15 native calls, then generated `MethodAccessor` bytecode). Still, a megamorphic `invoke` site (many different methods through one call site) cannot be optimized like a direct call.
* **Boxing**: `invoke(Object...)` boxes primitives and allocates the varargs array on each call.

For hot paths, use `MethodHandle`/`LambdaMetafactory`, or generate code at build time (annotation processors, MapStruct, Spring AOT).

### Strong encapsulation (Java 16/17)
`setAccessible(true)` on JDK internals now throws:

```
java.lang.reflect.InaccessibleObjectException:
  Unable to make field private final byte[] java.lang.String.value accessible:
  module java.base does not "opens java.lang" to unnamed module @1b6d3586
```

Options, in order of preference: upgrade the library that does this; use a supported API; as a last resort `--add-opens java.base/java.lang=ALL-UNNAMED`. For your own modules, `opens com.shop.domain to com.fasterxml.jackson.databind;` grants deep reflection to a specific framework only.

### Reflection and native images
GraalVM native image performs closed-world analysis: classes, methods and fields accessed reflectively must be declared at build time (`reflect-config.json`, `@RegisterReflectionForBinding`, Spring AOT `RuntimeHints`). Unregistered access fails at run time with `ClassNotFoundException`/`NoSuchMethodException`. This is a major reason frameworks are moving from runtime reflection to build-time code generation.

### Security and correctness pitfalls
* Deserialization gadgets: frameworks that instantiate arbitrary classes by name from input (polymorphic Jackson with default typing, Java serialization) enable remote code execution. Never enable default typing on untrusted input; use allow-lists (`PolymorphicTypeValidator`).
* Modifying `final` fields via reflection is undefined for static finals and for record/hidden-class fields (throws), and the JIT may have constant-folded the old value.
* `getDeclaredMethods()` order is unspecified — do not rely on it for behavior.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Reflection lets code inspect and invoke classes, methods and fields at run time; it powers Spring, Jackson, Hibernate and JUnit. Use it for infrastructure, not business logic, cache lookups, and prefer method handles or build-time code generation on hot paths. Java 17's strong encapsulation and native images restrict uncontrolled reflection.

**Must know:**
* `Class`, `Field`, `Method`, `Constructor`, `getDeclared*` vs `get*`.
* Generic type arguments survive in declaration metadata (`ParameterizedType`).
* `setAccessible` limited by modules; `--add-opens` / `opens ... to`.
* JDK 18 reimplemented core reflection with method handles.
* Native images need reflection metadata.

**Common follow-ups:**
* How does Spring find constructor parameters' generic types?
* Reflection vs `MethodHandle` performance?
* Why does my library fail with `InaccessibleObjectException` on Java 17?

**Red flags:** reflection for ordinary dispatch; uncached `getMethod` in loops; enabling Jackson default typing on public endpoints.
