# What are switch expressions

---

## 🟢 Junior Level

### What is it?

Starting with Java 14 (preview in 12/13), `switch` can be used as an **expression** that produces a value, and it has a new arrow form `case X ->` that **does not fall through**. This removes the classic bugs of forgotten `break` statements.

**Analogy:** The old switch is a railway with a junction where the train keeps rolling into the next track unless you pull a lever (`break`). The new switch is a vending machine: choose a button, get exactly one item.

```java
import java.time.DayOfWeek;

public class SwitchIntro {
    public static void main(String[] args) {
        DayOfWeek day = DayOfWeek.SATURDAY;

        // Old style statement
        int lettersOld;
        switch (day) {
            case MONDAY:
            case FRIDAY:
            case SUNDAY:
                lettersOld = 6;
                break;
            case TUESDAY:
                lettersOld = 7;
                break;
            default:
                lettersOld = 8;
        }

        // New style expression
        int letters = switch (day) {
            case MONDAY, FRIDAY, SUNDAY -> 6;
            case TUESDAY                -> 7;
            case THURSDAY, SATURDAY     -> 8;
            case WEDNESDAY              -> 9;
        };
        System.out.println(letters + " " + lettersOld);
    }
}
```

### Key points

- `case A, B ->` groups several labels.
- Each arrow branch is an expression, a block, or a `throw`.
- No fall-through, no `break` needed.
- The whole `switch` has a value you can assign or return.
- For enums, **exhaustive** coverage means no `default` is needed (the compiler checks).

## 🟡 Middle Level

### 1. `yield` for block bodies

When a branch needs several statements, use a block and `yield` the result:

```java
String describe(int code) {
    return switch (code) {
        case 200, 201 -> "OK";
        case 404 -> "Not found";
        case 500 -> {
            log("server error");
            yield "Error";           // yield returns the value from the block
        }
        default -> {
            if (code >= 400) yield "Client/Server problem";
            yield "Unknown";
        }
    };
}
```

`yield` is a contextual keyword; you can also use it with the old colon form:

```java
int v = switch (s) {
    case "a":
    case "b":
        yield 1;
    default:
        yield 0;
};
```

Do not mix `->` and `:` in the same switch — compile error.

### 2. Exhaustiveness

A switch **expression** must cover every possible input, otherwise it does not compile:

```java
enum Level { LOW, MEDIUM, HIGH }

int weight(Level l) {
    return switch (l) {          // no default needed - all constants covered
        case LOW -> 1;
        case MEDIUM -> 5;
        case HIGH -> 10;
    };
}
```

If you add `CRITICAL` later, this fails to compile — a **desirable** property (the compiler finds every place to update). Adding `default` silences that; prefer it only when truly needed. For enums, the compiler injects a synthetic default throwing `MatchException` (Java 21) / `IncompatibleClassChangeError` (earlier) if a new constant appears via separate compilation.

### 3. Switch on strings, enums, ints, wrappers

```java
String category = switch (extension.toLowerCase()) {
    case "jpg", "png", "gif" -> "image";
    case "mp3", "wav"        -> "audio";
    default                  -> "other";
};
```

Supported types: `byte/short/char/int` (and wrappers), `String`, enums; in Java 21 also any reference type via **pattern matching** (see [What is pattern matching for switch](12.%20What%20is%20pattern%20matching%20for%20switch.md)).

### 4. Statement vs expression forms

```java
switch (level) {                // arrow STATEMENT: no value, not required to be exhaustive for enums
    case LOW -> System.out.println("low");
    case HIGH -> System.out.println("high");
    default -> {}
}
```

### 5. Common mistakes

- Using `return` inside a switch expression's branch — illegal (can't jump out of an expression); use `yield` or restructure. Same for `break`/`continue` leaving the expression.
- Forgetting `default` for `int`/`String` switches in expression form → "does not cover all possible input values".
- Mixing colon and arrow labels.
- Assigning side effects in each branch when a pure expression is clearer.
- `null`: a switch over a `String`/enum still throws `NullPointerException` for `null` (unless using Java 21 `case null`).

## 🔴 Senior Level

### 1. Bytecode

- Int/enum/char cases compile to `tableswitch` (dense) or `lookupswitch` (sparse) — O(1)/O(log n).
- `String` switches compile to a two-step: `hashCode()` `lookupswitch`, then `equals` check, then a second `tableswitch` over an index. Collisions are handled by chained equals.
- Enum switches use a synthetic `$SwitchMap$` array in an anonymous class (`Outer$1`) mapping `ordinal()` → dense index, protecting against reordering across compilations. Java 21 pattern-switch uses `invokedynamic` with `SwitchBootstraps.typeSwitch/enumSwitch`.
- Arrow form generates identical bytecode patterns minus the fall-through jumps.

```bash
javap -c -p SwitchIntro | grep -E "tableswitch|lookupswitch|invokedynamic"
```

### 2. Semantics worth knowing

- **Definite assignment** works better: `final int x = switch ...;` — each branch either yields or throws, so `x` is definitely assigned.
- A `throw` branch is the idiomatic way to reject impossible states:

```java
return switch (state) {
    case NEW -> 0;
    case RUNNING -> 1;
    case DONE -> 2;
    default -> throw new IllegalStateException("Unexpected: " + state);
};
```

- Type of a switch expression: standalone vs poly expression. If used in an assignment/invocation context, each branch is checked against the target type; otherwise the result type is derived like a conditional (`boxing`, numeric promotion, lub). `var x = switch(...) { case A -> 1; default -> 2.0; }` → `double`.

### 3. Design guidance

- Prefer **exhaustive enum/sealed switches without `default`** — "closed world" modelling; compiler-checked evolution.
- Keep branches small; delegate to methods.
- A switch that picks behaviour by type is a candidate for polymorphism **unless** the hierarchy is closed and the operation is external (sealed types + pattern switch — the visitor pattern replacement).
- For string-based dispatch from config, switch is fine; a `Map<String, Handler>` is preferable if handlers must be extensible at runtime.

```java
Map<String, java.util.function.IntBinaryOperator> ops = Map.of(
        "+", (a, b) -> a + b,
        "*", (a, b) -> a * b);
```

### 4. Performance

Switch is not a bottleneck: JIT turns tables into jump tables or binary search; string switches hash the string (cached hash in `String`). Micro-benchmarks show differences below noise compared with `if/else` chains for small N; for large N use switch. Megamorphic dispatch through virtual calls is slower than a switch over a sealed hierarchy's tag, but pattern switch performance has improved significantly in 21+ (typeSwitch caching).

### 5. Migration with tooling

IntelliJ: "Replace with enhanced switch"; OpenRewrite recipes can migrate fall-through-free switches. Run tests: **behaviour changes** happen if the old switch relied on intentional fall-through — the converter only suggests when no fall-through exists.

Backwards compat: compile with `--release 8` and arrows will fail — the feature needs `--release 14+`. Libraries that must support Java 11 should not adopt it.

```java
// Java 21 integration with sealed types (preview of next question)
sealed interface Shape permits Circle, Square {}
record Circle(double r) implements Shape {}
record Square(double side) implements Shape {}

static double area(Shape s) {
    return switch (s) {
        case Circle c -> Math.PI * c.r() * c.r();
        case Square q -> q.side() * q.side();
    };
}
```

## 🎯 Interview Cheat Sheet

**30-second pitch:** Switch expressions (final in Java 14) return a value, use `case A, B ->` arrow labels with no fall-through, use `yield` in blocks, and must be exhaustive. For enums (and sealed types in 21) that lets the compiler flag missing cases.

**Must-know:**
- Arrow vs colon forms; don't mix.
- `yield` for multi-statement branches.
- Exhaustiveness required for expressions.
- No `return`/`break`/`continue` out of an expression.
- `null` selector → NPE (unless `case null` in Java 21).

**Common follow-ups:**
- Difference between switch statement and expression?
- What if a new enum constant is added? (Compile error when no default; `MatchException` on separate compilation.)
- How is a String switch compiled?
- Why prefer no `default` with enums?

**🚩 Red flags:**
- Still relying on accidental fall-through.
- Adding a blanket `default` that hides missing cases.
