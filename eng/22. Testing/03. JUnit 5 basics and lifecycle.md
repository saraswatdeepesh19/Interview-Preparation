# JUnit 5 basics and lifecycle

---

## 🟢 Junior Level

**JUnit 5** is the standard testing framework for Java. It is composed of three parts:

* **JUnit Platform** – launches test engines (used by IDEs, Maven, Gradle).
* **JUnit Jupiter** – the new programming model (`@Test`, extensions) and the engine that runs it.
* **JUnit Vintage** – an engine to run old JUnit 3/4 tests.

Dependency (Maven):

```xml
<dependency>
  <groupId>org.junit.jupiter</groupId>
  <artifactId>junit-jupiter</artifactId>
  <version>5.11.0</version>
  <scope>test</scope>
</dependency>
```

Spring Boot's `spring-boot-starter-test` already includes it.

### Analogy
A test class is like a lab exam: before each student (test) enters, the room is reset (`@BeforeEach`); after leaving, it is cleaned (`@AfterEach`). Before the whole day, the lab is opened (`@BeforeAll`); at the end, it is locked (`@AfterAll`).

### Minimal example

```java
import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class StackTest {

    private java.util.Deque<Integer> stack;

    @BeforeEach
    void setUp() {
        stack = new java.util.ArrayDeque<>();
    }

    @Test
    @DisplayName("push then pop returns the same element")
    void pushPop() {
        stack.push(7);
        assertEquals(7, stack.pop());
    }

    @Test
    void popOnEmptyThrows() {
        assertThrows(java.util.NoSuchElementException.class, () -> stack.pop());
    }
}
```

Notes: test classes and methods may be package-private in JUnit 5 (no need for `public`). `@Test` is `org.junit.jupiter.api.Test` – *not* the JUnit 4 one.

## 🟡 Middle Level

### Lifecycle annotations

| Annotation | Runs | Static? |
|---|---|---|
| `@BeforeAll` | once before all tests in class | yes (unless `PER_CLASS`) |
| `@BeforeEach` | before every test | no |
| `@AfterEach` | after every test | no |
| `@AfterAll` | once after all tests | yes (unless `PER_CLASS`) |

By default JUnit creates a **new instance of the test class per test method** (`Lifecycle.PER_METHOD`). Instance fields are therefore fresh for every test – this is what gives isolation. With `@TestInstance(Lifecycle.PER_CLASS)` one instance is reused: `@BeforeAll` can be non-static, but you are now responsible for resetting state.

```java
import org.junit.jupiter.api.*;

@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class ExpensiveResourceTest {

    private Object resource;

    @BeforeAll
    void init() { resource = new Object(); }   // non-static allowed

    @Test void a() { Assertions.assertNotNull(resource); }
    @Test void b() { Assertions.assertNotNull(resource); }
}
```

### Order of execution
`@BeforeAll` -> (`@BeforeEach` -> `@Test` -> `@AfterEach`) x N -> `@AfterAll`. Superclass `@BeforeEach` runs before subclass ones; `@AfterEach` in reverse.

### Assertions API

```java
import static org.junit.jupiter.api.Assertions.*;
import java.time.Duration;

assertAll("user",
        () -> assertEquals("Ann", user.name()),
        () -> assertTrue(user.age() >= 18));     // reports all failures

IllegalArgumentException ex =
        assertThrows(IllegalArgumentException.class, () -> new Age(-1));
assertEquals("age must be >= 0", ex.getMessage());

assertTimeoutPreemptively(Duration.ofMillis(200), () -> service.compute());
```

`assertTimeout` runs in the same thread and waits for completion; `assertTimeoutPreemptively` runs in another thread and aborts - beware, thread-bound resources (e.g. Spring transactions) will not be visible there.

### Disabling, conditions, tags

```java
@Disabled("bug JIRA-123")
@EnabledOnOs(OS.LINUX)
@EnabledIfEnvironmentVariable(named = "CI", matches = "true")
@EnabledForJreRange(min = JRE.JAVA_17)
@Tag("slow")
```

### Assumptions
`Assumptions.assumeTrue(cond)` *aborts* (skips) a test rather than failing it – useful for environment checks.

### Differences from JUnit 4

| JUnit 4 | JUnit 5 |
|---|---|
| `@Before` / `@After` | `@BeforeEach` / `@AfterEach` |
| `@BeforeClass` / `@AfterClass` | `@BeforeAll` / `@AfterAll` |
| `@Ignore` | `@Disabled` |
| `@RunWith`, `@Rule` | `@ExtendWith` |
| `@Test(expected=...)` | `assertThrows` |
| `@Category` | `@Tag` |

### Common mistakes
* Importing `org.junit.Test` with Jupiter -> test is silently *not run*.
* Mixing JUnit 4 `@RunWith(SpringRunner.class)` with Jupiter tests.
* Static state shared among tests; with parallel execution it explodes.
* Forgetting `maven-surefire-plugin` >= 2.22 (older versions do not detect JUnit 5).

## 🔴 Senior Level

### Architecture of the Platform
`Launcher` discovers tests via `TestEngine` implementations (`junit-jupiter-engine`, `junit-vintage-engine`, ArchUnit, Cucumber, jqwik...). Each engine returns a tree of `TestDescriptor`s. Build tools only talk to the Launcher, so you can add new kinds of test engines without touching Maven/Gradle.

### Execution model and parallelism
Jupiter runs test methods sequentially by default. Enable concurrent execution via `junit-platform.properties`:

```properties
junit.jupiter.execution.parallel.enabled=true
junit.jupiter.execution.parallel.mode.default=same_thread
junit.jupiter.execution.parallel.mode.classes.default=concurrent
junit.jupiter.execution.parallel.config.strategy=fixed
junit.jupiter.execution.parallel.config.fixed.parallelism=4
```

Synchronise shared resources with `@ResourceLock("DB")`, force exclusivity with `@Isolated`. Parallel execution typically yields 2-3x faster suites for CPU-light tests but exposes hidden shared state – make that a deliberate migration.

### Test ordering
Do not rely on order. If necessary (e.g. a scripted workflow), use `@TestMethodOrder(MethodOrderer.OrderAnnotation.class)` with `@Order`. Default order is deterministic but intentionally non-obvious (hash-based on method name). Use `MethodOrderer.Random` in CI periodically to catch order dependencies.

### Dynamic tests

```java
import org.junit.jupiter.api.DynamicTest;
import org.junit.jupiter.api.TestFactory;
import java.util.stream.Stream;
import static org.junit.jupiter.api.Assertions.assertTrue;
import static org.junit.jupiter.api.DynamicTest.dynamicTest;

class PalindromeDynamicTest {

    @TestFactory
    Stream<DynamicTest> palindromes() {
        return Stream.of("level", "noon", "radar")
                .map(s -> dynamicTest("palindrome: " + s,
                        () -> assertTrue(new StringBuilder(s).reverse().toString().equals(s))));
    }
}
```

Dynamic tests are generated at runtime; note that `@BeforeEach`/`@AfterEach` run once for the whole factory, not for each dynamic test.

### `@TempDir`, `@RepeatedTest`, `TestInfo`, `@Timeout`

```java
@Test
void writesFile(@TempDir java.nio.file.Path dir, TestInfo info) throws Exception {
    java.nio.file.Path f = dir.resolve("out.txt");
    java.nio.file.Files.writeString(f, "hello");
    Assertions.assertEquals("hello", java.nio.file.Files.readString(f));
    System.out.println(info.getDisplayName());
}

@RepeatedTest(5)
@Timeout(value = 1, unit = java.util.concurrent.TimeUnit.SECONDS)
void repeated() { /* detects flaky behaviour early */ }
```

### Production concerns
* **Reports**: Surefire/Failsafe XML publish to CI test tabs.
* **Class loading cost**: huge suites with Spring contexts dominate time, not JUnit. Reuse contexts (see [SpringBootTest and MockBean vs MockitoBean](12.%20SpringBootTest%20and%20MockBean%20vs%20MockitoBean.md)).
* **Native/GraalVM**: JUnit 5 supports native-image testing via the Native Build Tools plugin.
* **Custom behaviour**: write [extensions](07.%20JUnit%205%20parameterized%20tests%20nested%20classes%20and%20extensions.md) rather than inheritance base classes.

## 🎯 Interview Cheat Sheet

**30-second pitch:** JUnit 5 = Platform + Jupiter + Vintage. Tests are methods annotated with `@Test`; a new class instance is created per test, with `@BeforeEach/@AfterEach` for per-test setup and `@BeforeAll/@AfterAll` for class-level setup. Extensions (`@ExtendWith`) replace JUnit 4 runners and rules.

**Must know:**
* Lifecycle annotations and order; per-method instance default; `PER_CLASS`.
* `assertThrows`, `assertAll`, timeouts.
* `@Disabled`, conditions, `@Tag`, assumptions.
* JUnit 4 -> 5 migration table.
* Parallel execution config, `@ResourceLock`.

**Common follow-ups:**
* Why is `@BeforeAll` static? (Because instance doesn't exist yet in PER_METHOD mode.)
* Difference between `assertTimeout` and `assertTimeoutPreemptively`?
* How do you run only "fast" tests? (`@Tag` + Maven `groups`.)

**Red flags:** importing the wrong `@Test`; relying on test order; shared static mutable state.
