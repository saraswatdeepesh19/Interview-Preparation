# AssertJ vs Hamcrest assertions

---

## 🟢 Junior Level

JUnit's built-in `assertEquals(expected, actual)` is fine for simple checks, but it reads awkwardly and gives weak messages for complex objects. Two libraries improve that:

* **AssertJ** – *fluent* assertions: `assertThat(actual).isEqualTo(expected)`. IDE auto-completion shows every valid check for the type.
* **Hamcrest** – *matchers*: `assertThat(actual, is(expected))`. Matchers are small composable objects (`is`, `equalTo`, `hasItem`, `containsString`).

Both ship with `spring-boot-starter-test`.

### Analogy
`assertEquals` is a yes/no gate guard. AssertJ is a guard who speaks in sentences ("the list has 3 items and contains Ann"); Hamcrest is a guard who checks you against a checklist of reusable rules.

### Example

```java
import org.junit.jupiter.api.Test;
import java.util.List;

import static org.hamcrest.Matchers.containsString;
import static org.hamcrest.Matchers.hasItem;
import static org.hamcrest.Matchers.hasSize;

class AssertionStyleTest {

    @Test
    void assertJ() {
        List<String> names = List.of("Ann", "Bob", "Cid");

        org.assertj.core.api.Assertions.assertThat(names)
                .hasSize(3)
                .contains("Bob")
                .startsWith("Ann")
                .doesNotContain("Zed");
    }

    @Test
    void hamcrest() {
        List<String> names = List.of("Ann", "Bob", "Cid");

        org.hamcrest.MatcherAssert.assertThat(names, hasSize(3));
        org.hamcrest.MatcherAssert.assertThat(names, hasItem("Bob"));
        org.hamcrest.MatcherAssert.assertThat("hello world", containsString("world"));
    }
}
```

Tip: statically import only **one** `assertThat` per file to avoid ambiguity. In new code, prefer AssertJ.

## 🟡 Middle Level

### Why AssertJ is usually preferred
1. **Discoverability** – type-specific assertions appear after the dot.
2. **Readable failures** – describes expected vs actual with context.
3. **Rich API** – collections, strings, dates, `Optional`, `Path`, exceptions, `CompletableFuture`, `Duration`.
4. **Extensible** – custom assertions, soft assertions, recursive comparison.

### Collections

```java
import static org.assertj.core.api.Assertions.*;

record User(String name, int age) {}

List<User> users = List.of(new User("Ann", 30), new User("Bob", 17));

assertThat(users)
        .extracting(User::name)
        .containsExactly("Ann", "Bob");

assertThat(users)
        .filteredOn(u -> u.age() >= 18)
        .singleElement()
        .extracting(User::name)
        .isEqualTo("Ann");

assertThat(users).extracting("name", "age")
        .contains(tuple("Ann", 30));
```

### Exceptions

```java
assertThatThrownBy(() -> Integer.parseInt("x"))
        .isInstanceOf(NumberFormatException.class);

assertThatIllegalArgumentException()
        .isThrownBy(() -> validate(-1))
        .withMessageContaining("negative");

assertThatNoException().isThrownBy(() -> validate(1));
```

### Soft assertions
Collect all failures instead of stopping at the first:

```java
import org.assertj.core.api.SoftAssertions;

SoftAssertions.assertSoftly(softly -> {
    softly.assertThat(user.name()).isEqualTo("Ann");
    softly.assertThat(user.age()).isGreaterThan(18);
});
```

### Recursive comparison (objects without `equals`)

```java
assertThat(actualDto)
        .usingRecursiveComparison()
        .ignoringFields("id", "createdAt")
        .isEqualTo(expectedDto);
```

### Hamcrest: where it still shines
* **Spring MockMvc** `content().string(containsString(...))`, `jsonPath("$.items", hasSize(2))`.
* **RestAssured** `body("name", equalTo("Ann"))`.
* **Mockito** `argThat(...)` and Hamcrest-based `MockitoHamcrest`.
* Custom matchers by extending `TypeSafeMatcher<T>`, composable with `allOf`, `anyOf`, `not`.

```java
import org.hamcrest.Description;
import org.hamcrest.Matcher;
import org.hamcrest.TypeSafeMatcher;

class IsEven extends TypeSafeMatcher<Integer> {
    @Override protected boolean matchesSafely(Integer n) { return n % 2 == 0; }
    @Override public void describeTo(Description d) { d.appendText("an even number"); }
    static Matcher<Integer> even() { return new IsEven(); }
}
```

### Comparison table

| Aspect | AssertJ | Hamcrest |
|---|---|---|
| Style | fluent chain | matcher objects |
| IDE help | excellent | moderate (static imports) |
| Soft assertions | built in | no |
| Recursive object comparison | yes | no |
| Failure messages | very good | good |
| Use in MockMvc/RestAssured DSL | via `assertThat(result)` | native |
| Custom extension | custom `AbstractAssert` | custom `Matcher` |

### Common mistakes
* **Forgetting the terminal assertion**: `assertThat(x);` asserts nothing. Enable the IDE inspection or use Error Prone.
* Using `isEqualTo` on `BigDecimal` where scale matters (`2.0` vs `2.00`); use `isEqualByComparingTo`.
* Using `assertTrue(list.contains(x))` – failure message is just "expected true".

## 🔴 Senior Level

### Custom domain assertions
Create a vocabulary tailored to your domain:

```java
import org.assertj.core.api.AbstractAssert;

record Order(String id, String status, java.math.BigDecimal total) {}

class OrderAssert extends AbstractAssert<OrderAssert, Order> {

    private OrderAssert(Order actual) { super(actual, OrderAssert.class); }

    static OrderAssert assertThat(Order actual) { return new OrderAssert(actual); }

    OrderAssert isPaid() {
        isNotNull();
        if (!"PAID".equals(actual.status())) {
            failWithMessage("Expected order %s to be PAID but was %s", actual.id(), actual.status());
        }
        return this;
    }
}

// usage: OrderAssert.assertThat(order).isPaid();
```

AssertJ can generate these via the assertions generator plugin; for large domains this makes tests read like specifications.

### Async and awaiting
Use AssertJ with **Awaitility** rather than sleeping:

```java
import static org.awaitility.Awaitility.await;

await().atMost(java.time.Duration.ofSeconds(5))
       .untilAsserted(() -> assertThat(repository.count()).isEqualTo(3));
```

### Performance and internals
AssertJ assertions allocate small objects per call; irrelevant in tests except for huge collections. `usingRecursiveComparison()` uses reflection and is O(size of object graph) - avoid for 100k-element lists, prefer `extracting` + `containsExactly` or compare serialized snapshots. Be explicit with `ignoringFieldsMatchingRegexes` and `withEqualsForType`.

### Pitfalls with generics and type inference
* `assertThat(Optional.of(1)).hasValue(1)` – typed `OptionalAssert`.
* `assertThat(map).containsEntry("k", "v")` and `containsOnlyKeys`.
* With streams, `assertThat(stream)` converts to a list (consumes the stream).
* Comparing `double`: `assertThat(0.1+0.2).isCloseTo(0.3, within(1e-9))`.

### Strategy for large teams
* Standardise on **AssertJ** via a Checkstyle/ArchUnit rule that bans `org.junit.Assert.*` and Hamcrest in new tests.
* Use OpenRewrite recipes (the "Migrate to AssertJ" testing recipes) to convert JUnit assertions automatically.
* Keep JSON payload assertions with `JSONAssert`/`JsonUnit` for tolerant comparison (ignore order/extra fields).

### Error messages as a diagnostic tool
Prefer `assertThat(list).containsExactlyInAnyOrder(...)` to `assertEquals(Set.of(...), new HashSet<>(list))` – the former prints "elements not found / unexpected" lists, saving minutes per failure in CI.

## 🎯 Interview Cheat Sheet

**30-second pitch:** AssertJ offers fluent, type-aware, IDE-friendly assertions with excellent failure messages, soft assertions, and recursive comparison. Hamcrest offers composable matcher objects and remains common in MockMvc and RestAssured DSLs. Prefer AssertJ for plain unit tests.

**Must know:**
* `assertThat(actual).isEqualTo(...)` vs `assertThat(actual, is(...))`.
* `extracting`, `containsExactly`, `filteredOn`, `usingRecursiveComparison`.
* `assertThatThrownBy`, `SoftAssertions`.
* `isEqualByComparingTo` for `BigDecimal`.
* Incomplete `assertThat(x);` asserts nothing.

**Common follow-ups:**
* When would you write a custom matcher or assertion?
* How do you assert on async results? (Awaitility.)
* How to compare objects without `equals`?

**Red flags:** `assertTrue(a.equals(b))`, `assertEquals(true, ...)`, tests with only `assertNotNull`.
