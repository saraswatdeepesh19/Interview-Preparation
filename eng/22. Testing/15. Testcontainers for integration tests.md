# Testcontainers for integration tests

---

## 🟢 Junior Level

**Testcontainers** is a Java library that starts real infrastructure — PostgreSQL, Kafka, Redis, RabbitMQ, LocalStack, any Docker image — in **throwaway Docker containers** for your tests, and stops them afterwards. Tests run against the same software as production instead of fakes or in-memory substitutes.

```java
@SpringBootTest
@Testcontainers
class InvoiceIT {

    @Container
    @ServiceConnection                       // Spring Boot 3.1+: wires spring.datasource.* automatically
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16-alpine");

    @Autowired InvoiceService invoices;

    @Test
    void persistsInvoice() {
        Invoice saved = invoices.issue(new IssueInvoice("C-1", new BigDecimal("120.00")));
        assertThat(invoices.byId(saved.id())).isPresent();
    }
}
```

What happens: Testcontainers pulls the image (once), starts the container on a random free port, waits until PostgreSQL accepts connections, and `@ServiceConnection` passes the JDBC URL, user and password to Spring.

## 🟡 Middle Level

### Before `@ServiceConnection`: `@DynamicPropertySource`

```java
@Container
static KafkaContainer kafka = new KafkaContainer(DockerImageName.parse("apache/kafka-native:3.8.0"));

@DynamicPropertySource
static void props(DynamicPropertyRegistry r) {
    r.add("spring.kafka.bootstrap-servers", kafka::getBootstrapServers);
}
```

Use this for anything Spring Boot can't auto-detect (custom properties, URLs of your own services).

### Wait strategies
A container being "started" is not the same as "ready":

```java
GenericContainer<?> api = new GenericContainer<>("acme/pricing-stub:1.4")
        .withExposedPorts(8080)
        .waitingFor(Wait.forHttp("/actuator/health").forStatusCode(200))
        .withStartupTimeout(Duration.ofSeconds(60));
```

Modules (PostgreSQL, Kafka, MongoDB...) ship correct wait strategies; for generic containers, always define one or you will get flaky "connection refused" failures.

### Lifecycle choices

| Style | Lifetime | Use when |
| --- | --- | --- |
| `@Container` instance field | Per test method | Rare; very slow |
| `@Container static` field | Per test class | Default with JUnit extension |
| Singleton (static initializer in a base class, no `@Container`) | Whole JVM; Ryuk cleans up at exit | Many test classes sharing one DB — fastest |
| `@TestConfiguration` bean with `@ServiceConnection` (Boot 3.1+) | Tied to the cached Spring context | Shared config + `spring-boot:test-run` for local dev |

```java
@TestConfiguration(proxyBeanMethods = false)
public class TestInfra {
    @Bean @ServiceConnection
    PostgreSQLContainer<?> postgres() { return new PostgreSQLContainer<>("postgres:16-alpine"); }

    @Bean @ServiceConnection(name = "redis")
    GenericContainer<?> redis() { return new GenericContainer<>("redis:7-alpine").withExposedPorts(6379); }
}
```

Import it with `@Import(TestInfra.class)`, or run the whole app locally against it via a `TestApplication` main class (`SpringApplication.from(App::main).with(TestInfra.class).run(args)`).

## 🔴 Senior Level

### How it works under the hood
* Talks to Docker through the Docker API (docker-java), honoring `DOCKER_HOST`, Docker Desktop, Colima, Podman or Testcontainers Cloud.
* Starts a sidecar **Ryuk** container that removes every container/network labeled with the session ID when the test JVM dies — even after `kill -9`. Some locked-down CI environments disable Ryuk (`TESTCONTAINERS_RYUK_DISABLED=true`); then you must clean up yourself.
* Maps container ports to random host ports; always use `getMappedPort()`/`getHost()`, never hardcode `localhost:5432`.

### Speed at scale
* **Pin image tags** (`postgres:16.4-alpine`), and pre-pull or mirror images in CI (`hub.image.name.prefix` for a private registry) to avoid Docker Hub rate limits.
* **Reuse locally**: `.withReuse(true)` + `testcontainers.reuse.enable=true` in `~/.testcontainers.properties` keeps containers between runs (not for CI: state leaks).
* **Parallelism**: share one container but isolate data — one schema or database per test worker, or truncate between tests. Starting one PostgreSQL per test class with 200 classes costs minutes.
* **Faster images**: `apache/kafka-native` (GraalVM) starts in ~1 s vs ~10 s for JVM Kafka; Redpanda for Kafka-API tests; tmpfs mounts for databases: `.withTmpFs(Map.of("/var/lib/postgresql/data", "rw"))`.

### Networking between containers

```java
Network net = Network.newNetwork();
PostgreSQLContainer<?> db = new PostgreSQLContainer<>("postgres:16-alpine")
        .withNetwork(net).withNetworkAliases("db");
GenericContainer<?> app = new GenericContainer<>("acme/legacy-reporting:2.1")
        .withNetwork(net)
        .withEnv("DB_URL", "jdbc:postgresql://db:5432/test")   // container-to-container uses alias + internal port
        .dependsOn(db);
```

Host → container uses mapped ports; container → container uses network aliases and *internal* ports.

### Testing failure modes
**Toxiproxy** (`ToxiproxyContainer`) sits between your app and a dependency and injects latency, bandwidth limits or connection cuts — the right way to test timeouts, retries and connection pool recovery against a real database or broker:

```java
ToxiproxyContainer.ContainerProxy proxy = toxiproxy.getProxy(postgres, 5432);
proxy.toxics().latency("slow-db", ToxicDirection.DOWNSTREAM, 2_000);
// assert: request fails fast with a timeout and Hikari recovers after the toxic is removed
```

### When not to use it
Pure domain logic (no I/O) — plain unit tests are 1000× faster. Testcontainers belongs to the integration layer: repositories, messaging adapters, migrations, and a few end-to-end service tests.

## 🎯 Interview Cheat Sheet

**30-second pitch:** Testcontainers runs real dependencies in disposable Docker containers for tests, so integration tests use the production database, broker and cache versions. Spring Boot's `@ServiceConnection` wires them automatically; I share containers per JVM, pin images, isolate data per test, and use Toxiproxy to test failure handling.

**Must know:**
* `@Testcontainers` + `@Container` lifecycle; static = per class.
* `@ServiceConnection` (Boot 3.1+) vs `@DynamicPropertySource`.
* Wait strategies prevent "started but not ready" flakiness.
* Ryuk cleans up; random mapped ports.
* Singleton containers and data isolation for speed.

**Common follow-ups:**
* How do you run Testcontainers in CI without Docker-in-Docker issues?
* Testcontainers vs H2 vs embedded Kafka?
* How do two containers talk to each other?

**Red flags:** hardcoded ports; `latest` image tags; one container per test method; using it for pure unit logic.
