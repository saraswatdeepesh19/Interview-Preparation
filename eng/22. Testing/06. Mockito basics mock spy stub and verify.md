# Mockito basics mock spy stub and verify

---

## 🟢 Junior Level

**Mockito** is the most popular Java mocking framework. It lets you create fake versions of dependencies at runtime, tell them what to return, and check how they were used - without writing manual stub classes.

Core vocabulary:

| Concept | API | Meaning |
|---|---|---|
| Mock | `mock(Type.class)` | Fake object; all methods return defaults (`null`, `0`, `false`, empty collections) |
| Stub | `when(m.call()).thenReturn(x)` | Tell the mock what to return |
| Verify | `verify(m).call()` | Assert the method was called |
| Spy | `spy(realObject)` | Real object, but you may override/verify some methods |

### Analogy
A mock is a remote control without a TV: you decide what each button "returns" and afterwards check which buttons were pressed.

### Minimal example

```java
import org.junit.jupiter.api.Test;
import java.util.Optional;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.mockito.Mockito.*;

interface UserRepository { Optional<String> findNameById(long id); }

class WelcomeService {
    private final UserRepository repo;
    private final MailSender mailSender;

    WelcomeService(UserRepository repo, MailSender mailSender) {
        this.repo = repo;
        this.mailSender = mailSender;
    }

    String welcome(long id) {
        String name = repo.findNameById(id).orElse("guest");
        mailSender.send(name, "Welcome!");
        return "Hello " + name;
    }
}

interface MailSender { void send(String to, String text); }

class WelcomeServiceTest {

    @Test
    void sendsMailAndGreets() {
        UserRepository repo = mock(UserRepository.class);
        MailSender mail = mock(MailSender.class);
        when(repo.findNameById(1L)).thenReturn(Optional.of("Ann"));

        String result = new WelcomeService(repo, mail).welcome(1L);

        assertEquals("Hello Ann", result);
        verify(mail).send("Ann", "Welcome!");
    }
}
```

Dependency: `org.mockito:mockito-core` (plus `mockito-junit-jupiter` for the extension) - both included in `spring-boot-starter-test`.

## 🟡 Middle Level

### Annotations and the JUnit 5 extension

```java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.*;
import org.mockito.junit.jupiter.MockitoExtension;

@ExtendWith(MockitoExtension.class)
class WelcomeServiceAnnotatedTest {

    @Mock UserRepository repo;
    @Mock MailSender mail;
    @InjectMocks WelcomeService service;   // constructor injection, then setter/field

    @Test
    void usesGuestWhenUnknown() {
        when(repo.findNameById(2L)).thenReturn(java.util.Optional.empty());

        service.welcome(2L);

        verify(mail).send("guest", "Welcome!");
    }
}
```

`MockitoExtension` initialises annotations *and* activates **strict stubs** (unused stubbings fail the test).

### Stubbing cheat sheet

```java
when(repo.findNameById(anyLong())).thenReturn(Optional.of("Ann"));
when(repo.findNameById(-1L)).thenThrow(new IllegalArgumentException("bad id"));
when(service.next()).thenReturn(1, 2, 3);                       // consecutive calls
when(repo.findNameById(anyLong())).thenAnswer(inv -> Optional.of("user" + inv.getArgument(0)));

doThrow(new RuntimeException()).when(mail).send(any(), any());   // void methods
doNothing().when(mail).send(eq("x"), anyString());
```

### Argument matchers - the all-or-nothing rule
If you use a matcher for one argument you must use matchers for **all** arguments:

```java
verify(mail).send(eq("Ann"), anyString());   // OK
// verify(mail).send("Ann", anyString());    // InvalidUseOfMatchersException
```

### Verification modes

```java
verify(mail, times(1)).send("Ann", "Welcome!");   // default
verify(mail, never()).send(eq("Bob"), any());
verify(mail, atLeastOnce()).send(any(), any());
verify(mail, atMost(3)).send(any(), any());
verify(mail, timeout(500)).send(any(), any());    // async tolerant
verifyNoInteractions(mail);
verifyNoMoreInteractions(repo);                   // use rarely
InOrder inOrder = inOrder(repo, mail);
inOrder.verify(repo).findNameById(1L);
inOrder.verify(mail).send(any(), any());
```

### Spy: partial mocking

```java
List<String> real = new ArrayList<>();
List<String> spy = spy(real);

spy.add("a");
verify(spy).add("a");
assertEquals(1, spy.size());               // real behaviour

doReturn(100).when(spy).size();            // NOT when(spy.size()) - that would call the real method
```

Use `doReturn(...).when(spy)` to avoid executing the real method during stubbing. Spies are a smell if used on the class under test; they are acceptable for legacy code (see [Testing legacy code](22.%20Testing%20legacy%20code.md)).

### Default answers
* `RETURNS_DEFAULTS` - nulls/zeros/empty collections/empty `Optional`.
* `RETURNS_SMART_NULLS`, `RETURNS_DEEP_STUBS` (smell), `CALLS_REAL_METHODS`.

### What Mockito cannot (easily) do
* Stubbing `equals()`/`hashCode()`.
* Mock `private` methods (and you shouldn't want to).
* Mock `static` and constructors - possible since inline mock maker; see [Mockito advanced](09.%20Mockito%20advanced%20ArgumentCaptor%20strict%20stubs%20and%20mocking%20static.md).

### Common mistakes
1. Stubbing a mock you then never call (strict stubs will flag it).
2. Forgetting to initialise mocks (`@Mock` without extension -> NPE).
3. Mixing raw values and matchers.
4. Stubbing inside `thenReturn(mock.other())`, causing `UnfinishedStubbingException`.
5. Verifying implementation details after already asserting output.

## 🔴 Senior Level

### How Mockito works internally
* **Mock creation** - Mockito generates a subclass (subclass mock maker) or *instruments the class itself* (inline mock maker, default in Mockito 5) via **ByteBuddy**. An `MockMethodInterceptor`/advice intercepts each call and routes it to an `InvocationContainer` holding stubs and recorded invocations.
* **`when(mock.call())`** - the call `mock.call()` is executed first on the mock and recorded in a *thread-local* "ongoing stubbing" state (`ThreadSafeMockingProgress`); `when(...)` then picks up that last invocation and returns an `OngoingStubbing`. This explains why `when(spy.realMethod())` runs the real method and why interleaving stubbing across statements is fragile.
* **Matchers** are pushed onto a thread-local stack in `ArgumentMatcherStorage` at call time of `eq()`, `any()`...; that is why they cannot be extracted into helper variables (`ArgumentMatcher` returned from `any()` is `null`/`0`).

### Inspecting what happened

```java
import org.mockito.Mockito;
import org.mockito.invocation.Invocation;

Mockito.mockingDetails(mail).getInvocations()
       .forEach((Invocation i) -> System.out.println(i));
Mockito.mockingDetails(mail).printInvocations();
```

### Performance
Creating a mock costs ~tens of microseconds after class generation is cached; the *first* mock of each type is slower (bytecode generation, ~10-50 ms). Large suites that create thousands of mocks are fine; the real cost is the Spring context, not Mockito. Inline mock maker retransforms loaded classes, which can slow JVM startup slightly. Use `Mockito.clearInlineMocks()` in rare long-lived test JVMs (rarely needed).

### Concurrency and thread-safety
Invocation recording is synchronised, but the stubbing state is thread-local. Do not stub from a thread different from the one that invokes `when(...)`. When verifying asynchronous interactions:

```java
import static org.mockito.Mockito.*;

executor.submit(() -> mail.send("Ann", "Welcome!"));
verify(mail, timeout(1000).times(1)).send("Ann", "Welcome!");
```

### Production design guidance
* Use constructor injection so `@InjectMocks` is not even needed: `new Service(repo, mail)` is clearer and compile-checked.
* Avoid `lenient()` unless a stub is shared in `@BeforeEach` and used by only some tests.
* Prefer **BDDMockito** (`given(...).willReturn(...)`, `then(mail).should().send(...)`) for Given-When-Then readability.
* Use `mockito-core` + `-javaagent` on JDK 21+ to avoid dynamic-agent warnings (see [Test doubles mock stub and fake](05.%20Test%20doubles%20mock%20stub%20and%20fake.md)).

```java
import static org.mockito.BDDMockito.*;

given(repo.findNameById(1L)).willReturn(Optional.of("Ann"));
service.welcome(1L);
then(mail).should().send("Ann", "Welcome!");
then(mail).shouldHaveNoMoreInteractions();
```

## 🎯 Interview Cheat Sheet

**30-second pitch:** Mockito creates test doubles at runtime. `mock()` makes a blank fake, `when().thenReturn()` stubs behaviour, `verify()` asserts interactions, and `spy()` wraps a real object for partial mocking. With `MockitoExtension` you get `@Mock`, `@InjectMocks`, and strict stubs.

**Must know:**
* `when/thenReturn`, `doReturn/when` (void methods and spies), `thenThrow`, `thenAnswer`.
* Matchers: all-or-nothing rule.
* `times/never/atLeast/timeout/InOrder`.
* Spy semantic: real methods called unless stubbed.
* `@ExtendWith(MockitoExtension.class)` vs `@MockitoBean` (Spring).
* Mockito 5 defaults to inline mock maker (can mock final classes).

**Common follow-ups:**
* Mock vs spy?
* Why `doReturn` for spies?
* What happens if a stubbing is unused? (Strict stubs -> `UnnecessaryStubbingException`.)

**Red flags:** `verifyNoMoreInteractions` everywhere; mocking `String`/`List`; deep stubs; spy on SUT.
